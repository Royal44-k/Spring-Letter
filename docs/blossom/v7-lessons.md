# 风起之时：这轮制作留下的经验

2026-11-20。用于后续迭代，不把研究数量或自动检查数量当作作品质量。

## 从“可以操作”到“有值得做的选择”

旧版花开、散聚与按钮切换能展示技术，却不能独自支撑一段游戏。第一版三庭追风也暴露了同类收集重复：加风结和计时并未充分改变策略。第二次设计因此明确分工：初庭学习选路，风廊在先行与同行间取舍，终庭切换慢行和踏风。最低目标、全收与回巢时机提供不同投入程度；失误不夺走已获得的花灵。

陈星汉的 [Flow in Games 原文](https://jenovachen.com/flowingames/Flow_in_games_final.pdf)提出把难度选择嵌入玩家行动，而不是只由系统替玩家安排。本作借鉴这一原则；它不是证明本作已经足够有趣的实验结果。将来仍需观察真实玩家如何理解目标、在哪停下，以及是否愿意再走一遍。

## 让同行者具有规则意义

角色不能只跟在身后发光。游絮有自己的位置与跟随速度，落后会改变银灵是否可接取；玩家改变步调，关系才发生作用。可读性同时依靠花冠变化、尾迹、方位盘和一句提示，避免只靠颜色或声音传达规则。暂停必须冻结同行者，重开不能继承上一程的花灵。

## 实机画面会推翻参数上的想象

第一轮加贴图后仍像展台：灰白天空、规则岸圈、等距宽叶和强反射一起削弱了材质区分。第二轮改了天空线性亮度、自然细叶簇、岸石与水色，默认主花改为有叶色与花心的粉瓷。月银虹彩保留为参考系列。真实表面图不能代替造型、构图、环境尺度和演出；目前人物与地形仍明显是程序造型。

竖屏实拍还发现说明文字覆盖踏风触点。只有“控件在视口内”的检查不足以验收布局，需要检查控件之间的占位关系。方位盘也不能只按固定比例投影：远侧花巢会被画布裁掉，必须保留边缘方位。

## 提示音不等于配乐

这轮使用七个免费许可真实乐器采样，编写十六小节主题，按庭园、追风、水庭、寄信调配器与节奏。环境声、脚步和动作反馈独立混音。需要检查的是游戏实际输出，而不仅是音频节点数或离线乐谱。

Web Audio 暂停会停止音频时钟；MediaRecorder 的媒体时间可能留下无包区间。判断静音时必须保留帧 PTS，不能把拼接后的 PCM 秒数直接当作墙钟秒数。测量能证明有输出、无削波、静音有效，不能证明旋律已经达到专业配乐的艺术水平。

## 新旧系统交界比单模块更容易出错

终庭种核花杯与追风花巢的交互范围曾有一小片重叠。常规路线测试能完成寄信，却漏掉从右侧走近时 E 被花巢截走的问题。处理方式是明确优先级：正在进行的活动先响应，空闲时眼前可执行的拾种/安放操作优先，远处的指路提示则不阻挡花巢。相应的可见提示与按键行为必须一致。

## 留住可追溯的工作成果

先固定候选文件，再做普通输入游玩、实机截图与声音录制。任何运行时代码改动都会生成新候选，旧证据留在独立目录，不用旧截图证明新版本。免费素材保存作者、官方来源、许可、处理步骤和散列；公开作品的设计可供研究，公开可见不等于资产可以复制。

未解决的长期空间：庭院尺度仍小、支线影响仍偏轻、角色表演与叙事演出有限、缺少真实新玩家盲测及多设备性能证据。这些不能用“电影级”“AAA”或更多测试条数来替代。
