# 春信 0.5 工程产品化审读

2026-11-21。范围：只读源码、现有规则测试、发行脚本与 FINAL_QA；没有运行浏览器，也没有把静态推断写成实机复现。行号对应本轮开始时的 0.5 源码，后续集成可能移动。

## 判断

目前没有发现必须立即停止本地体验的 P0。规则模型对损坏输入的防御、固定候选发行和实际完整路线验证已经存在；主要缺口是玩家资产保护、信息一致性和非开发者交付。商业可用不能以 213 条检查取代这些产品行为。

## P1：开始新旅途会立即覆盖唯一进度

- 位置：`spring-letter/index.html:11`、`src/main.js:149`、`:178`、`:84`。
- 触发：玩家已有旅途，返回扉页后点击最显眼的“走进花庭”。它直接调用 `startGame(false)`，创建新状态并在结尾立即 `save()` 到唯一 `journey:v1`。
- 影响：没有明确“新旅程”语义，没有确认或可恢复备份；一次普通点击即可丢失已完成章节和支线。单独保留的偏好/追风纪录不能恢复故事。
- 建议：有档时将“续写春信”作为主要操作；重开明确提示并保留可恢复整档。备份应涵盖旅途、个人最好纪录、偏好、启程前检查点，而不是只拷贝主线。
- 验收：有档→重开取消完全不变；确认重开→旧档可恢复；备份写入失败时不得继续破坏性替换。

## P1：读取失败与没有旅途被混为一谈

- 位置：`src/game-model.js:57–60`、`src/main.js:83`、`:150`；`tests/initial-restore.test.js:5`。
- 触发：存档 JSON 损坏、未来版本、存储访问受限。`restore` 都返回全新状态；`storageGet` 将访问异常吞为 null；扉页只看 `started`，因此隐藏继续。
- 影响：本应保留供恢复/迁移的原档会在下次新局保存时被覆盖，玩家也不知道发生了什么。规则层返回安全状态合理，产品层必须另外保留原始错误分类。
- 建议：存档服务区分 empty / ready / legacy / invalid / unsupported / unavailable；提供导出与导入预览。未来版本拒绝导入，不静默变新档；损坏原文可导出诊断。错误不得伪装为“已保存”。
- 验收：版本 2、非法 JSON、配额失败不改变有效主档；导入前只预览；恢复/导入先备份原档。

## P1：多标签页可能互相覆盖

- 位置：`src/main.js:84`、`:149`、`:280`、`:207`。
- 触发：同源两个标签页都续玩同一存档，任一每五秒自动保存或失焦保存。没有 revision、storage 事件或会话所有权校验。
- 影响：较旧标签页可回写旧进度，较新的旅程无提示消失。
- 建议：聚合存档单键提交，写前检查读取的版本标识是否仍匹配；冲突时保留内存旅程、暂停自动写入并提供重新读取/导出，不自动覆盖另一标签页。
- 验收：A、B 同时读取；A 保存后，B 提交收到 conflict，磁盘仍是 A 内容。需说明 localStorage 无真正跨标签 CAS，本轮检测能减少误覆盖，不能声称强事务锁。

## P1：完成序章后的导航信息互相争抢

- 位置：`src/main.js:171`、`:277`、`:322`、`src/journey-guide.js:51–56`、`src/story-director.js:59`。
- 触发：新玩家完成序章。主目标说右前花巢追风，世界指路仍指中心沉睡的花；走到中心又自动进入花朵近看。附近支线按钮与 E 分别走独立入口；追风时 E 的优先级与按钮入口并非同一个决策器。
- 影响：玩家难以理解“现在最应该做什么”，新版追风和旧版花朵教学像两个并列教程。这是可玩性问题，也是交互架构问题。
- 建议：统一下一步目标/交互意图来源，显示一个主目标和可收起的可选发现；提供可回看的短操作卡。首个 90 秒以移动→第一封具体委托→看到环境改变建立闭环，再展开花朵表达。
- 验收：同一位置可见按钮、E、触屏操作产生相同动作；新玩家不需要阅读设置长段文字；中途返回时恢复当前目标而不是重新播放教程。

## P2：发行包对非开发者仍有环境门槛

- 位置：`启动春信.cmd:4–8`、`scripts/package-v7.py:59`、`README.md:5`。
- 触发：收件电脑没有 Node.js；启动器回落 `node`，系统报未找到命令，只有暂停。包验证只使用制作机 `D:/NodeJS/node.exe`，证明文件可服务，不证明干净 Windows 可双击运行。
- 建议：至少明确检测 Node、输出可操作错误与免费官方来源；把 ZIP 定位为需 Node 的离线包。后续正式渠道优先公开 HTTPS 浏览器体验，或带运行时桌面包，须另行验证分发许可、安装/升级/卸载与多设备性能。此审计不授权对外部署。

## P2：运行期故障缺少统一恢复出口

- 位置：`src/main.js:284`、`:309`、`:354`、`:207`。
- 触发：加载结束后某帧抛出 JS 异常。`init` 的 catch 不覆盖后续 RAF；下一帧已先排队，可能持续抛错。WebGL contextlost 有明确覆盖层但普通运行异常没有同等处理。
- 建议：统一一次性故障捕获，停止输入/时间/声音，保留最后有效档，提供下载诊断与重新打开。诊断只含版本、错误摘要、画质和匿名性能，不偷偷上传。

## P2：易读与可达选项不完整

- 位置：`src/main.js:142`、`src/story-director.js:41`、`src/resonance-ui.js:5–8`、`index.html:31`。
- 事实：已有字幕 live status、独立音量、轻缓动态、原生 dialog、键盘部分替代；不应把这些归零评价。
- 缺口：序章固定八秒翻页，无暂停阅读选项；大量移动端辅助字为 9–11px；没有字号设置；踏风屏幕按钮仅 pointerdown/up，键盘焦点 Space/Enter 不对应按钮的“按住”语义；对话框未设置 aria-labelledby。
- 建议：先加可停留的阅读/字幕选项和文字大小，补齐屏幕动作按钮的键盘语义，并以键鼠与触屏分别核对说明。不要宣称完整无障碍认证。

## P2：游戏内制作名单落后于实际素材

- 位置：`src/main.js:144`。
- 触发：打开“作品与来源”。文案仍说声音由程序构建，未列新增 VSCO2CE 采样与 v7 表面图作者，且仍标 FIRST PLAYABLE EDITION。
- 建议：制作名单展示当前版本、真实资产/音乐作者及本地许可链接，完整外部来源沿用 ASSET_SOURCES 与 THIRD_PARTY_LICENSES。不要写不存在的人类作曲者或授权协议。

## 本轮优先完成的三个工程交付

1. **存档保险箱**：单键权威整档、旧槽迁移、固定重开备份、最近有效恢复点、导出/导入预览、冲突/配额/未来版本错误可见。它直接保护玩家投入。
2. **统一旅途入口与下一步**：有档默认继续、新局确认；教学、支线、追风、送种由同一操作意图仲裁，清楚区分主目标和可选活动。它直接减少首分钟流失。
3. **可报告的发行体验**：显式 Node 检测、本地版本/素材名单、运行异常一次性恢复页、简单匿名反馈导出（本地文件，不自动上传）。它让外部试玩家能进入、描述问题和返回，不要求看开发者控制台。

以上是静态审读的风险与验收建议，不是修复完成声明。实现与实际验证应另记结果。

## 0.6 发行时的状态补记

原审读保留作历史记录。本轮已落实聚合存档、旧档迁移、备份/导入预览/导出、显式临时模式、冲突保护和先保存再完成的寄信/回退事务；本机隔离浏览器验证见 [存档UI九项记录](../../spring-letter/evidence/v8/save-ui-2026-11-21T05-53-20-657Z/report.json)。主线改为三封具体来信，统一下一程并保留手动回访追踪，源花近看不再自动抢夺漫游镜头；见 [普通输入新主线](../../spring-letter/evidence/v8/play-2026-11-21T04-16-46-256Z/report.json)。

制作名单已改为0.6和真实素材来源，启动器有Node缺失提示；桌面包仍需Node。另有无Node运行依赖的HTTP静态包，根和嵌套路径已检验。两个包分别解压逐文件HTTP校验，正式5192已核对同一构建。见 [最终验收](../../spring-letter/FINAL_QA.md)、[包验证](../../spring-letter/evidence/v8/package.json)。

一般JS运行异常的统一恢复出口、字号与阅读停留选项、物理手机实测仍是后续事项。新存档冲突检测也不是跨页面原子锁。持续运行显示资源有界，但批量花型切换仍有长帧；不能把本次通过表述成所有工程风险已经消失。
