# v7 环境美术：让花庭有空气、土壤与生长

2026-11-20。用户对 0.4 的反馈是缺少可玩性、情境音乐与精致可信的画面。本页只记录环境这一条线的诊断、采用决定和接线；不把通过测试当成审美达到电影或商业 AAA 水准。

## 先改什么

0.4 的主要问题不在于模型数量：天空直接使用粉灰渐变；圆形岛面缺少真实色彩纹理与尺度；多数建筑的粗糙度和金属度接近，塑料感较强；水面干涉线比水体和倒影更抢眼。因此本轮先统一晨间空气、矿物质表面和水深，再在首庭边缘增加少量自然野花。主花仍是超现实的银、晶与花尘，不把所有表面涂成同一类写实材质。

## 已写入的实现

- `atmosphere-garden.js`：一层球形背景绘制，冷蓝天顶、暖白日晕、低对比云层和两层远岸；夜间保留星点，花尘近景仍能转暗。它是解析式天空，不是体积云或真实远山模型。
- `world.js`：普通石材由粉紫亮面改为暖灰/苔灰哑光，金属只留给有意义的器物。水纹大幅降亮，并由浅水衰减控制，保留已有真实平面反射，不把纹理线当作“真实水”。
- `world-polish.js`：起始庭四处不对称边缘草簇与细小野花，中间花体、出生路径、杯桌和西行探索入口保持空旷。风动只更新着色器时间；轻缓动态为零摆动。花与草并未加入新碰撞或改变可走区域。
- 四张官方 1K JPG 共 3,748,725 字节；全部与官方元数据 MD5 一致，Pillow 实际解码为 1024×1024，颜色/法线 RGB，粗糙度 L。来源账本与 CC0 原文位于 `spring-letter/public/assets/v7/`。

## 接线与预算

```js
import {createGardenAtmosphere, loadGardenSurfaces} from './atmosphere-garden.js';
const atmosphere = createGardenAtmosphere(); // 与旧 object/update/dispose 接口兼容
scene.add(atmosphere.object);
// 现有 normal/rough 加载之后，compileAsync 预热之前：
const gardenSurfaces = await loadGardenSurfaces({world, landscape, renderer});
// 释放时先恢复材质钩子，再释放各世界：
gardenSurfaces.dispose(); atmosphere.dispose();
```

天空仍只有一个背景 draw；新草甸三个基础 draw，阴影与反射会在各 pass 中再次绘制。新增四张 1K 纹理；没有新光源、额外渲染目标或每帧纹理分配。地面三向颜色/法线/粗糙度比旧材质增加纹理读取，因此整体帧时间须由主任务实测；本页不据 draw 数承诺帧率。

建议根场景采用冷灰蓝雾、较暖日光，曝光约 .85，日环境强度约 .6；最终数值以主任务实景对照为准。所有入口、任务、保存和相机逻辑由原控制器保持。

## 已有验证与仍待观察

`tests/garden-art.test.js` 四项通过：背景资源只释放一次；纹理载入不改变世界几何、路径和共享法线图；部分加载失败全部回收；新首庭草甸避让主要交互空间。原 `world-polish.test.js` 三项继续通过。纹理解码记录为 `evidence/v7-surface-decode.json`。这些是 CPU 与文件检查，不能代替最终整包 shader 编译、性能、日夜画面和审美复核。

仍有的边界：地表是纹理与法线而非高精扫描几何；树叶和角色依旧为风格化程序模型；水深是基于庭院位置的近似；远岸只是天空中的空气透视层；主花厚玻璃内部折射没有由本模块解决。提升是否足够明显，必须用玩家实际看到的整包镜头对照判断。

## 对首次接线截图的第二轮修订

复看 `evidence/v7/art-cover.png` 和 `art-arrival.png` 后，首次接线仍不达标：低空大面积灰白，青灰宽叶呈规则摆放，首庭描边圈强化了展台感，拱门缺少大尺度表面变化；草丛中的小花只有花头而没有茎。这些是图像里可见的问题，不把“贴图载入成功”当作解决。

本轮决定在原晨光方案内继续深化，没有更换玩法布局或下载更多素材：

- 天空使用线性光照值，低空由 `.66/.75/.72` 降为 `.30/.45/.50`，更快向蓝色天顶过渡；太阳方向与世界日光的 `(-7,8,5)` 对齐。薄云仍是一层解析背景，不额外加泛白覆盖层。
- 草叶重新建模为薄而尖的弯曲片。此前复用的观赏叶片有 0.12 米中央隆起，缩小时仍显得厚重。新草有暗根、尖端、四组自然绿实例色，岸边草和首庭草共享风动材质；原 70 片规则宽叶改成 224 片分簇细草。
- 首庭 40 朵野花补齐花茎，增加 32 块不同旋转与尺度的低矮岸石。石形为受侵蚀的细分几何，使用已有 CC0 灰泥纹理，没有导入大模型。两者分别增加一个实例批次；首庭不再绘制一整圈描边，地面用苔土斑块与碎石接合。
- 拱门和岸石回到非金属、较高粗糙度的暖矿物色；三向纹理同时使用已有灰泥法线和粗糙度。米级斑驳与潮湿层叠在真实细纹之下，避免只有颜色变化、没有尺度变化。投影法线采用 Three.js 已处理非均匀实例缩放的法线；法线数据不作颜色解码。
- 水体增加青绿深色，削弱原来近乎恒定的高亮项，让倒影和水下颜色共同存在；保留原有波纹和可选平面反射。
- 轻盈画质保留全部四处首庭草簇和全部后续岸边簇，草数量减半，隐藏微小野花的三个批次；通过交错实例顺序避免减半后丢失一整边。切回均衡或细腻不重建几何。轻缓动态继续停用草的摆动。

材质原则再次核对了 [Three.js MeshStandardMaterial 官方文档](https://threejs.org/docs/pages/MeshStandardMaterial.html)：石和植被的金属度归零，粗糙度与法线图按非颜色数据使用，颜色图使用 sRGB。此页据实际本地 Three.js 0.185.0 shader 源码检查投影与实例法线的接入位置，没有猜测或引入新依赖。

第二轮 CPU 验证：`garden-art.test.js`、`world-polish.test.js`、`landscape.test.js`、`camera-occlusion.test.js` 共 **17 项通过、0 失败**。覆盖新增草/花茎/岸石避让、低画质完整分布及恢复、所有路径和种植区域保持、状态不变及资源只释放一次。静态世界统计为 134 个 Mesh（含隐藏对象）、11 个实例批次、262,476 个总三角形；这不是实景帧内 draw/三角数，也不是 FPS 承诺。第二轮比第一轮多 2 个基础实例 draw，影子和倒影 pass 的重复绘制另计。四张素材文件与下载账本没有变化。

第二轮没有在美术分支启动 GPU 浏览器，实际 shader 编译、光照曝光、主花材质和最终镜头对照交由主任务统一验证；不能据上述 CPU 测试宣称画面已经达到电影或商业 AAA 水准。
