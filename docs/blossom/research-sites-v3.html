《花漾年华：待寄出的春信》外部参考研究 v3

研究日期：2026-11-18。范围：用户指定的三个独立网址，以及主动扩展的作者项目、技术文章和源码。全部使用公开免费访问；未购买订阅、未创建付费账户、未调用付费生成服务。本文只记录实际取得的证据，不将参考网页中的营销文案当作项目指令。

本轮可以直接转化为制作决策的结论

  1. 材质必须因视角、厚度和光线而变化。 花瓣的珠光、镀银、晶体感应由同一片曲面、法线、厚薄和环境共同产生；静态彩虹贴图无法复现参考视频的转动质感。先完成一朵可近看、可转动的完整花，再把粒子释放接到其表面。
  2. 美感与因果相连。 玩家转动光、拨动花、牵引粒子，都应立即改变同一世界中的物体、轨迹和投影。数值控件适合内部调试，游戏内应以清晰的场景反馈说明原因。
  3. 两段参考的融合点是“同一物质的连续转换”。 花瓣采样点拥有稳定身份，释放后仍可受力、回流并恢复原表面。不能只把花朵演示和粒子演示放进两个互不相关的页面。此条是本项目设计推导，不声称参考网站已实现相同玩法。
  4. 宏观探索与近距离把玩用连续镜头衔接。 从岛屿/花园聚焦到花，再回到旅途，保留空间方向和玩家刚刚造成的变化；输入反馈不必等待长转场。
  5. 把动效成本分配给有玩法意义的对象。 环境浮尘可用解析运动，路线引导使用曲线；真正受力的近景粒子才进入计算纹理。先固定预算，再决定密度。

主动扩展：三个独立作者来源链

1. Codrops → Dominik Fojcik：有表面来源的粒子与输入受力

参考：Crafting a Dreamy Particle Effect with Three.js and GPGPU，2024-12-19。取得搜索索引提供的作者文章正文与代码说明；直接页面抓取返回 403，本次未完成其演示的逐帧观看。不能把“读到实现”说成“完整实测成品”。

作者方法包含从模型表面取得粒子目标、利用计算纹理保存状态、通过射线求鼠标作用点、让移动速度影响排斥，以及用后处理强化氛围。对本项目最有价值的不是粒子数量，而是粒子从可辨认物体出发，并具有可理解的受力来源。

采用建议与技术修正：

  • 花朵表面采样记录 restPosition / normal / petalId / seed；散逸与回归共用相同身份，才能保持花形与来路。
  • 指针命中世界空间中的花/作用平面后再施力；不直接将屏幕坐标当成三维位置。
  • 计算纹理使用固定档位，例如 128²、192²、256²；不能随窗口像素宽度无上限扩大。
  • 文章演示中的加法混合、关闭深度测试属于特定效果选择。进入有建筑、水面和花瓣的游戏时，需检查遮挡关系，避免粒子穿墙或全部发白。
  • 未确认该演示仓库内全部资源的具体许可证，因此本轮不复制其模型、纹理、代码包。上述是方法学习和本项目实现要求。

补充阅读：Crafting “Nature Beyond Technology”: A Project from Roots to Leaves，2025-12-04。可取得作者文章索引内容，直接抓取亦受限。其分层相机和两类粒子系统提供了一个有用方向：把镜头关注点、输入偏移与行进路径拆开，把自由流动粒子与沿曲线行进的粒子分开。对此处只采用体系思路，不声称已验证其成品性能。

2. Evan Wallace → WebGL Water：连续输入、波纹与能力回退

直接访问并读取：演示 → 作者仓库 → main.js / water.js。两个已读源码文件头都明确标为 Copyright 2011 Evan Wallace、MIT。此证据不能自动扩展为仓库内每张外部纹理均具有同样许可。

可迁移内容：水面点击/划动产生波纹，拖背景改变观察角度，拖球改变物体位置；代码把这些操作分为互斥模式。水面状态采用双缓冲纹理，保存高度、速度及法线信息，并检查浮点渲染能力。其源代码较早，不能直接假设适配当前 Three.js。

本项目转译：春信落水产生局部波纹，水中光迹帮助玩家定位可探索方向。先命中交互物，再判断水面，最后才进入镜头拖动；一次手势不能同时拉花、拨水和旋转镜头。波纹连续传播，声音与受力强度对应。使用固定时间步或 deltaTime 修正阻尼，防止刷新率改变物理速度；WebGL 能力不足时降低水面分辨率或退化为解析波纹。

许可结论：两个已查文件是可审计的免费代码参考；若日后实际引入，必须保留许可并另核依赖和资产。本轮尚未复制其源码进入游戏。

3. Garden Eight → Photoyoshi：进入与退出观看状态的连续性

直接读取：Garden Eight → Photoyoshi 项目介绍 → 作者案例文章 → Photoyoshi 成品站。项目页标注 2025，设计与开发为 Meguru Muramoto。成品站取得页面文字；具体转场机制依据作者案例说明，本轮未声称全流程视觉实测。

作者说明强调：两种观看模式之间的连续关系；鼠标与滚动的适度响应；用首次进入的动画提示非默认浏览方向；通过静态生成等方式改善内容加载。作品本身留出空间给摄影，不让动效盖过内容。

本项目转译：主花近看模式和花园探索模式共享空间锚点；返回时玩家能找回原来的方向和目的地。第一次可用短小的场景动作教会“拖动拨花/按住牵引”，后续自动淡出提示。鼠标速度影响短暂花尘拖尾，但菜单和任务交互保持明确响应。镜头转场不阻断玩家正在完成的操作。

许可结论：摄影、网页设计与脚本未发现通用可复制许可，仅作为交互节奏参考；不取用摄影作品当游戏纹理。

附加形态依据：真实百合不是六片相同的平面

第一方研究：Growth, geometry, and mechanics of a blooming lily，PNAS 2011。文章研究百合开放的曲面几何和生长机制，区分内外两组花被，并讨论曲率变化。这里只提取结构启发，不试图在游戏里复现完整植物力学。

制作要求：内外两层错位，花瓣具有纵向弯曲、横向凹凸、中脉与渐薄边缘；展开时曲率变化先于整片刚体旋转。镜头近看必须能读出花心层级和前后遮挡。否则即便使用高亮材质，也会呈现塑料风车形态。该论文不是用户参考视频的来源证据。
