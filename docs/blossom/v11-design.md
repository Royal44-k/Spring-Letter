# 花漾年华：待寄出的春信 · 潮汐与远航

日期：2026-11-23。独立于金沙项目。沿用现有本地 Three.js 游戏；全部新增造型、交互与文字为项目原创，研究与素材只采用免费可用来源。

## 本次任务

用户已明确要求继续制作，保留已经认可的多种交互，修复花桥绿色波浪墙，补齐至少一个情境导入、八个主要环节和一个结局。结局承接“写自己的信、收下上一任的信、登岛得船、迎着曙光把信寄向远方”。执行采用现有浏览器平台，不增加账号、付费依赖或外部服务。

## 旅程与意义

序章《借来的春天》：弥从花尘中醒来。岑曾把故乡封存于方舟，如今留下三封等待回应的来信。远处有海，春天终究需要离开被保护的花庭。

1. **花光暗房**：叠放树、窗、花三张透明花笺，让禾的故乡重新透光。空间构图。
2. **纸翼渡风**：控制纸翼升降与侧移，穿越不同风场。连续操控。
3. **回声织信**：以三种音色写八拍回应，听完自己的作品。自由作曲。
4. **借花为桥**：把花尘织成真实可走的花路，跨台后重新归形。空间路径与有限资源；绿色挡墙修复必须有来源证据。
5. **留下两处春天**：亲手搬运两枚种核，选择照料的未来。可逆取舍。
6. **写给未曾谋面的人**：在海岸书桌写自己的收信人和正文；可以借一句开头，但必须亲自确认。以拖动印章落在信封、或等价键盘动作封缄。文字真实保存，可导出，绝不以 HTML 注入。
7. **潮汐留下的旧信**：观察涨退潮，在高处停留、沿显露的石脊前进。半途在旧邮亭读完并带走岑的一封信：保护使春天活下来，送出才让春天继续。到达小岛，潮水不造成死亡或丢信，危险时返回最近高石台。
8. **岸边的一叶舟**：探索小岛，找到岑留下的船。解开两侧缆绳，沿桅杆拉起花帆；键盘、鼠标和触屏都能完成，有清楚的完成反馈。信包装入舱内，船与角色都有真实三维呈现。
9. **一路繁花向海**：亲手掌舵，调整风帆迎风，沿海上浮光前进。将带来的种子随手撒向船侧，水面长出立体莲、百合、鸢尾等花，不同形态与配色形成航迹；没有计时死亡或强制刷分。沿途花群、海鸟、岛屿渐远，晨光渐明。

终章《收信人，尚在远方》：镜头慢慢拉远，弥与游絮在船上，两封信在同一只信袋中。最后由玩家作一个明确的启程动作，船朝曙光行进，出现“有些春天，只有送出去，才真正属于我们”。结束页展示自己的收信人、正文和岑的落款，允许保存纪念、继续看海、重访花庭。三种种核选择改变花海色调与结语，不阻断共同的远航。

开场花卉散聚、风笔、旧杯节奏、光中地址、记忆花姿和追风作为自由支线保留；不把它们凑入九个主要环节。

## 呈现与工程边界

- 新海岸章节使用独立可恢复的 voyage 状态与控制器，按阶段明确处理键鼠、触屏、相机、暂停和 UI；既有三封信与花桥仍由原模块管理。
- 花庭与海岸过渡有明确叙事和短淡入，保存种核安排后转场。不会直接把旧结局弹窗当成出海。
- 海岸是可行走的三维场景，近看信桌、潮石、旧邮亭、岛屿和船；航海是持续操作，不能只点击按钮播放。
- 每段都提供当前行动、场景可见目标、可撤销或恢复位置、键盘与触摸等价控制；非计时文本允许随意阅读。
- 旧版已结束存档可进入新增海岸篇；旧核心规则与备份格式继续兼容。写信、收旧信、登岛、解缆、航行里程分别保存；恢复清除残留速度和按键。
- 保留 0.7.1 的透明画布 / NaN 修复、反射保护与 WebGL 失败恢复界面。新海水 shader 的非线性输入均限定合法区间。
- 验证包括完整实际操作、旧存档续玩、刷新恢复、触屏和键盘、三种画质、画布像素、开场与所有新场景、最终本地发布与打包；不以无报错替代画面检查。

## 选择记录

采用“内陆已有五段 + 海岸四段”的一条连续旅程，避免重做用户认可内容，也避免添加几个互不相关的小关卡。借鉴案例只取空间、节奏、反馈方法；不复制商业游戏素材。自主推进是用户多轮明确要求，方案留档可审阅，不再添加重复确认关卡。
