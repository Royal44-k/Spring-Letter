# 海岸篇叙事与操作审查

日期：2026-11-23。审查范围：`voyage-controller.js`、`voyage.css`、`voyage-content.js`、`voyage-model.js` 当时工作版本。只读审查；本记录未修改被审文件，也未启动浏览器/GPU。作者正在并行修改，因此下列项是交给实施者的发现清单，不能当成最终版本仍有问题或已经修复的结论。

## 先修会阻断或违背操作意图的问题

| 优先级 | 位置与触发 | 用户后果 | 具体修正与验收 |
|---|---|---|---|
| P1 | `voyage-controller.js` 的 `readControls()` 返回布尔 `hoist`；`voyage-model.js` 的升帆调用 `axis(input.hoist)`，而 `Number.isFinite(true)` 为 false。 | 键盘 Space 与触屏长按升帆完全无效，只有拖动桅索的另一路径可以完成。 | 控制器给数值 0/1，或模型明确接受布尔值。用真实 Space 与触屏按住分别升满，并验证松手立即停止。孤立 CPU 合同探针已复现：模拟按住 3 秒后 `sail===0`。 |

这些问题已经及时发给主任务与控制器作者。探针是独立函数输入检查，不冒称正常游玩通关证据。

## 下一批影响理解与无障碍的细节

1. **按键返回合同要明确。** 当前 `handleKey()` 几乎对所有非编辑按键返回 true。主程序若因此 `preventDefault()`，Tab、Enter 激活按钮、Space 激活印章等浏览器默认行为可能全部消失。只对确实消费的游戏按键返回 true，文本输入、Tab 与可聚焦按钮保留原生行为；在根接线后用完整纯键盘流程验证。
2. **旧信有触屏可见的取消阅读入口。** 当前只出现“把这封信也带上”，键盘可 Escape 关，但触屏没有同等返回。可加“先合上”，再次走近继续读，已阅读状态不丢失。信袋关闭后的焦点应回到打开它的按钮。
3. **当前目标应显示行动，不重复章名。** `sync()` 用 `info.title`，而 `voyageStageInfo()` 已提供具体的 `hint`。例如潮汐拿到信前后，下一步应从“去旧邮亭”变为“带两封信沿石脊登岛”；标题重复不能完成这件事。
4. **落水恢复事件名称不一致。** 模型发 `recover`，控制器监听 `recovery/soft-return`，因此“回到高石、信仍在”这条反馈不会显示。统一事件名，回退后给短暂观察时间，不把无解释传送当作自然反馈。
5. **旧邮亭可操作距离统一。** 控制器显示按钮与开始读信用 2.25，模型命令允许 2.15。2.15–2.25 的狭缝内会看到按钮却被拒绝。使用同一常量或模型提供 `canRead`。
6. **别在不产生花的时候播放开花声。** 模型 `scatter` 冷却期间仍返回 `ok:true`、空事件；控制器据 ok 播放 sea-bloom。应按真实 `flower` 事件发声，避免“有声无花”。海上开花声的 `index` 可传累计花数，使用已写好的四种固定音型。
7. **键盘与触屏标签随设备变化。** 触屏不需要反复显示 WASD/右键，桌面提示也不应让人以为只支持拖动。当前长句可拆成“当前目的”与短操作帮助，不让海面底部被一整行教学占据。

## 需要实机矩形与截图确认的布局风险

这些是从 CSS 推导的候选风险，尚未当作浏览器复现结论。

- 390px 粗指针竖屏：动作面板 `bottom:155px`，方向键 `bottom:105px` 且高约 100px，两者垂直范围重叠。航行时帆角滑条位于面板左侧，可能挡住方向键的上键。须读取实际 `getBoundingClientRect()` 及点命中结果；使用分区网格或把帆角/动作放在右侧，不能只提高 z-index 转移谁被挡。
- 窄屏工具按钮设置为 30px 高，低于本项目方向键的 44px。长时间游玩中暂停、信袋与回正是常用操作，建议粗指针至少 44px，尤其不能被后置的 `max-width` 规则覆盖回 30px。
- 移动端软键盘使可用高度降低时，`max-height:500px` 规则会把写信纸缩为 44vw。需检查键盘弹出之后文字输入与封缄是否仍能滚动访问，别把“窄而高的竖屏”误当成“横屏”。
- 旧信与信袋都应检查最长文字、系统字体放大、窄横屏和面板滚动。完成页正文限高并独立滚动，键盘需要能把焦点带入阅读区，否则长信只能看首段。

## 叙事与结束页判断

九段结构成立：前三段的空间构图、飞行、作曲，接到花桥、种核安排，再进入亲笔、潮汐旧信、备舟、掌舵。不能把岛上走几步和登船按钮单独宣传成两个完整章节；设计现在把登岛与备舟合为第八段，是合理尺度。独立终章也没有抢走玩家亲手写下的正文，这一点应保留。

结局已经比泛化“拯救世界”更贴近主题：两封信、两处留下的花、解开的缆绳、船头的光，都与真实行动相连。保留“信尚未抵达，春天已经上路”这一句即可，不必每个层级再补一条意义相近的宣言。状态标题仍有“有些春天，送出去才属于我们”，可收为更具体的“弥与游絮，途中”。`CODA` 可直接写“终章”，中文语境更清楚。

岑的旧信最后一句目前预知玩家已经种下“两处春天”，会稍有机制说明塞进旧信的感觉。建议改为：“若有人问起这里，就告诉他你亲眼看见的样子。”这样岑交出的不只是任务，而是允许后来者亲自判断的空间。玩家种下的两处春天留给海上旁白和纪念信，因果更准确。

当前“船会继续往前”的文字需要视觉兑现。模型在 dawn 停船、complete 停止推进；如果世界模块另有只服务镜头的慢航，应确保船、人物、信袋、浪迹一起移动。若实景只轻摇不前进，避免宣称正在远航；主任务需检查完整结束演出，而不是只看到结束页就认为用户要求的曙光远航已经成立。
