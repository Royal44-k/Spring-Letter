# 花漾年华：待寄出的春信 — 情景与交互剧本 v4

2026-11-18｜独立主题｜制作剧本与最终呈现契约。本文保留完整叙事目标，不能把每条导演要求都视为已通过验收；本轮实际证据与仍有差距见[质量验收表](quality-rubric-v4.md)。已读正式构建报告包含26项普通输入检查和8项边界检查；旧花离开后姿态与序章重放演员的两项新增回归尚未计入这一批结果。

沿用[v3制作定稿](release-design-v3.md)与[v2叙事玩法蓝图](experience-blueprint.md)的四幕规则、支撑保护和两枚种核三种用途。本版把角色身份、开场、事件台词和三条可玩的支线收束成可直接落地的内容。新增脚本不要求购买配音、模型或音乐；可先用字幕、合成音节、现有场景和原创程序几何完成。

## 1. 故事的中心与事实边界

**一枚新生的花灵，在替故乡保存季节的方舟上，学会把“记住”变成“继续照料”。**

主题不是“遗忘比怀念更好”。旧记录保留了一段生活的完整性，当下的庭院需要继续生长，远方也值得收到种子；三件事都合理，却不能在这次航程里同时获得持续支持。玩家最后安排的是先照料哪两项，不是在决定谁值得活着。

人们离开故乡时，把种源、雨的节奏、季节光照和生活片段存入花。一次长风暴后，方舟启用保形协议，避免这些东西在漂泊中散失。风暴已过，保形结构仍在工作。修复过程中的花尘结出新种荚：这就是弥醒来的原因。旧系统不知道如何替下一段生活作决定，新生的照料者能够重新安排已有的花、光与材料。

宏大世界只通过当下可见关系出现：同一脉络从花瓣延伸到桥，桥通向穹顶，穹顶之外有其他方舟的问候灯。普通联络不等于播种；启程前，远方只有已有节点回应。向新地方发送可生长的种子，仍受终章“远方”用途约束。

必须保持的叙事事实：

- 花里的记录来自过去；记录中说“你”，也不是守园人正在实时观察玩家。
- 弥没有承接某个旧人的记忆或灵魂。能读取、重放一段记录，不等于成为记录中的人。
- 游絮有自己的动作与节律。它的第四拍是新回应，不是“亡者认出了你”的证明。
- 守园人离开花庭之后的去向，本篇没有证据。不要临时加一场死亡、牺牲或复活来制造感动。
- 两只旧杯与三道旧水痕不能直接推出“这里曾有第三个人”。其中一处是留给后来者的空位；是否有人后来坐过，本篇不擅自补证。
- 支线只影响玩家写入春信的细节、可重访的小景物与节律，不给第三枚种核，不改写三种结局的代价。

## 2. 角色与叙事声音

|角色|身份与欲望|如何被玩家认识|表达方式|避免的误读|
|---|---|---|---|---|
|弥 / 玩家|由修复花尘结出的新种荚，花庭称这种初醒的照料者为“送春者”。起初想把所有东西恢复成原样，后来学习安排下一步。|开场看见自己从微光中醒来；移动、启瓣、拨尘、归形都是其身体能力。|短促的动作与偶尔一句观察，不替玩家作长篇道德独白。|不是无所不知的救世主，也不是归来的守园人。|
|游絮 / 同行者|花庭里独立的新生命，想找到安全的停靠处；对玩家保持好奇，也会犹豫。|风廊先保持距离；玩家撤去推力后才主动靠近，接出第四拍。|翅瓣、停顿、绕行、四拍声纹；不加人类配音。|不是可操纵的工具，不因玩家选了某个结局就消失或枯萎。|
|岑 / 过去的守园人|曾负责花庭、记录季节与照料旅人。风暴中选择保形，离园前留下一段招待后来者的约定。|只通过署名刻痕、杯声、维护记录与短字幕出现。|所有字幕标“旧记录”；字句具体、克制，像给下一位值园人留下的交接。|不是实时NPC；去向未定，不写“岑的灵魂在游絮里”。|
|其他方舟 / 远方来信|与本地共享航道的其他生活节点，本篇不刻画其具体居民。|拱廊外有限的灯、方向与一次回答。|远处微光一问一答，不出现可漫游星系的界面承诺。|问候没有夹带种子；撤回“远方”预演不需要撤销已经播种的事实。|

三种字幕声部要能一眼分清：

1. **引言 / 场景叙述**：只给当前必要的空间与身份信息。不开口替玩家说“你终于懂了”。
2. **守园人·岑 / 旧记录**：带固定小标签与轻微残缺感；文本是已存档内容，不动态回答玩家的新问题。
3. **弥的观察**：使用第一人称时只说眼前事实，例如“它等我收回手，才靠近。”结局态度由玩家自己的安排表达。

“岑”是本版新定的原创署名，不是此前已确定的历史人物；不必在开场要求记住姓名。角色册可以随时回看身份，语音不是理解关系的前提。

## 3. 48秒实景开场：从花庭到一枚种荚

总时长48秒，六段各8秒；允许“下一段”与“直接启程”，可在角色册重看。每段字幕不超过50个汉字。全屏由独立按钮主动触发；进入游戏、播放引言或跳过引言都不暗中切全屏。

|时间|镜头与可见动作|字幕 / 声部|声音与节拍意向（需单独听审）|实施要点|
|---|---|---|---|---|
|0–8秒|现有浅水庭的斜俯总览，建立主花、杯桌与通往远方的拱廊。最终相机位置`[9.8,6,12.5]`、注视点`[-.5,1,-5]`。|引言：“离开故乡以后，方舟替人们保留了一个春天。”|庭的低频泛音与轻空气层缓入，为字幕留出空间。|从真实场景开场，不先放背景图或纯文字黑屏。本镜最终采用总览，不再把“低机位一滴水”写作已制作事实。|
|8–16秒|沿水面靠近两只杯子。两处杯纹先后出现，第三处只有旧水痕。|引言：“花记得雨。两只杯子，记得有人曾在这里等过。”|左杯两拍，右杯回应在最后一拍前停住；静音时水圈数量等价。|不显示完整答案与任务清单；此处建立一个可回看的疑问。|
|16–24秒|从杯纹抬到主花。同一花瓣轮廓先变成细密粉蓝点场，局部松开后回到原表面。|引言：“风暴过去，修复中的花尘结出一枚新种荚。”|银花高频泛音逐渐成为颗粒声，再落到单个温暖音节。|沿用同源表面ID、开度与坐标。不能用随机星空替换花，也不能切到另一段独立视频。|
|24–32秒|镜头落到玩家种荚，弥的核心第一次亮起。远处花形仍在，新的生命与旧记录同时存在。|弥·送春者：“你叫弥，是新醒来的送春者。你没有旧人的记忆，却能让花庭重新回应。”|种荚轻响一声，保持与旧杯不同的音色。|表现“新生”，不让整株花变成某个旧人肖像。可用近处少量花尘衬托，不许凭空改换主粒子采样目标。|
|32–40秒|视线回到空席。旧记录署名淡现，杯口的暖光停在尚无人占据的一侧。|守园人·岑 / 旧记录：“若有人先到，替我给后来的人留一杯。”|只留近处杯的余音；没有从远方响起的实时人声。|小标签一直在，清楚这是旧记录。没有制作配音时，字幕与音节就足够。|
|40–48秒|镜头退至普通游戏机位，弥已位于可走区域。花的开度回到本次开局值，浅水里露出一条未醒的路。|此刻：“先从眼前这朵花开始。让光穿过半开的花瓣，看看水下还藏着什么。”|两声清楚而轻的提示音；环境声保留。|结束后交还移动与E聚焦。不要再次跳切、重复出现同一段开场字幕或自动完成P1。|

镜头衔接的规则：

- 花体、点场与水中的投影保持同一空间锚点；相机接近与实体淡出不要同时大幅改变视场角。
- 16–24秒的明暗变化使用连续环境过渡。粒子更清楚时可以压暗背景，但不能让整座花庭突然消失。
- 每个画面至少保留一处上一段的视觉锚点：杯缘、花茎或水纹。回到玩法时保留玩家面向与前路方向。
- 轻缓动态模式缩短位移幅度、去掉镜头绕转，保留同样字幕与状态；跳过不丢失身份说明。
- 暂停、失焦、设置面板出现时，镜头、字幕计时与音节一起停。跳过后清除尚未播放的字幕/声音事件。
- `story.introSeen`只控制默认是否重播，不是关卡进度。重看不重置花、桥、种核或支线。

## 4. 四幕主线台词：信息跟在动作之后

每次最多一条，通常20–35字。新场景字幕不要覆盖尚未读完的关键操作提示；支线字幕优先级低于“桥正在承托你”等安全反馈。文字只补充画面尚不能独立表达的含义。

|事件ID|触发|台词|须有的画面证据|
|---|---|---|---|
|`garden.enter`|引言结束，或跳过引言后首次恢复控制|“我是弥。先让眼前这朵花，透进一束光。”|种荚与主花同时可见，前路未开。|
|`garden.overbloom`|首次全开后光未命中|“花全开了，光却散在四周。留一点含蓄试试。”|宽光斑与半开窄光带可比较。没有图形对比时只保留操作提示。|
|`garden.solve`|P1完成|“第三道水痕亮了。原来，路一直藏在花的影子里。”|三圈旧水痕与前路的顺序回应。|
|`garden.record`|P1后第一次听完整杯声|旧记录：“雨停之前，先把桌子擦干。下一位来的人，可能走了很远。”|杯纹与空席；文字不是假装亲耳听见尚未制作的配音。|
|`wind.enter`|进入风廊|“风并不总朝同一个方向。光团也会避开我的手。”|流线与局部推开，内侧横风有可见节律。|
|`wind.pushing`|近终点仍持续施力，短提示节流|“再靠近一点，就把手收回来。”|接收花的低速脉冲，不突然判失败。|
|`wind.arrive`|游光撤力后停稳|“我停下来，它才找到了落下的位置。”|逻辑光团停杯，玩家作用场消退。|
|`wind.reply`|游絮自主靠近并接第四拍|“旧杯回了三声。它却添了一声，像有自己的话。”|三次旧纹在前，游絮第四拍明确不同位置/色温。|
|`pool.enter`|首次进入倒影池|“这一捧花尘，只够撑起一段路。先走稳，再借给下一程。”|当前结构与下一锚位，材料身份标记保持相同。|
|`pool.middle`|首次到M，旧花投影出现|旧记录：“那场风太久。我们先把花合上，等一个能落地的地方。”|旧日投影标签；合瓣挡风，年份从外侧流过。|
|`pool.past`|看见保护与停滞两面后|“合上的花曾挡住风。可等待，也留在了花里面。”|幼芽受保护，却没有跟随外部年份生长。|
|`pool.solve`|抵达F|“同一捧花尘，已经带我穿过了水面。”|固定F台已抵达；曾回收、重建的材料身份始终相同。不要暗示抵达后会自动回收仍可使用的桥。|
|`finale.enter`|穹顶第一次聚焦|“两枚种核，三个愿望。我要先照料哪两种春天？”|两枚核心的身份可数，三用途预演可比较。|
|`finale.commit`|主动启程后|“这封春信写下的，是接下来愿意照料的生活。”|只发生所选的持续后果；第三用途保持其未获支持状态。|

## 5. 三条有操作差异的支线

支线的目的不是补三篇日志。每条至少包含发现、身体操作、空间变化和可重访结果。全部复用现有场地，不新增需要长距离寻路的地图。建议首见时各30–90秒，具体时长仍需玩家实测。

### A. 留一席 — 杯声创作

**位置**：栖光庭 `(-3.7, 1.9)`，现有两杯与空席旁。靠近出现“听听杯声”，E进入实景焦点。P1后旧三拍更清楚，但不把P1完成作为创作门槛。

**玩家做什么**：编一条自己的六拍杯声。每拍可选左杯、右杯或停顿，先试听，再“留在这里”。它是创作，不是照抄旧谱的密码。至少需要一拍发声；全为停顿时温和提示“留下一声，再给回声一点位置。”不设手速、节拍精确度或失败分数。

**三层反馈**：

- 操作瞬间，所选杯震出不同半径与色温的水圈，键盘1/2、鼠标/触屏均可选。停顿以一段空水线表示，不能只靠声音区分。
- 试听六拍按固定、舒缓的0.6秒间隔播放，末拍后再留0.6秒回应间隔。若游絮已同行且此曲已经保存，它在这段间隔后添一声；未同行时只保留余波，不假装它已建立关系。留白是可选创作内容，不强制左右杯都出声或第六拍休止。
- 保存后，空席旁出现弥的六拍水纹带。返程可重播、改写；原先两杯旧记录继续存在，不被新谱覆盖。

**剧情揭示**：旧刻字：“这只杯子没有写名字。来得晚的人，也该有个位置。”弥观察：“我不必学会一模一样的回答，也可以在这里留一声。”这说明空席面向后来者，不能把未出现的人编成第三名死者。

**奖励**：`story.branches.rhythm=true`；保存`story.motif`六拍；终章回信可提及玩家留下的节律，杯纹成为可见的个人痕迹。不给核心、货币、性能加成或更高道德评级。

**离开/恢复**：随时离开不中断主线。未按保存不设置完成；已保存的旧曲不因试编而丢失。存档损坏时只恢复默认空白草稿，不影响桥或结局。

### B. 光里的地址 — 照光显字

**位置**：风织廊 `(-3.8, -17.5)`，桌式日晷上放着一张带三处浅痕的信笺。此点在固定岛面上，不要求跨临时桥。扫光面板只控制这一组刻痕，不向P2逻辑光团施力。最终实物是信笺，不再称为叶背。

**玩家做什么**：移动一束低强度光，让信笺的三处刻痕分别显影。每处连续照到0.65秒即可留住轮廓，离开光束后仍保留已读部分；键盘1/2/3提供等价定位，不把像素级对准当难度。三段文字可任意顺序发现，不要求暗记或排唯一密码。

**可见结果**：信笺三段分别为“后来者”“有席”“此处”，已发现的文字留在纸面，当前照光位置有实景光点。三段齐全时，纸下的小回信显现，界面组合成“后来者，有席，此处”。远方节点的问候属于世界既有联络；不能把它当成已经向新地点播种。

**剧情揭示**：旧记录：“航道上的名字会改。若你找不到我，就把灯留给下一位。”弥观察：“这不是寄给一个人的地址。它在说：到了这里，你有地方停下。”宏大网络由一份具体的招待关系成立，不追加星系地名表。

**奖励**：`story.branches.light=true`；`story.lightFound`保存三个布尔值，允许分次找齐。纸面保留淡字，折叠回信留下可重访结果。终章回信提及“信笺上的邀请，终于被读到了”。

**重要边界**：这次问候只连接已有节点，不发送种子，不提前满足终章“远方”用途。没有光束时，标记仍有浮雕轮廓和可操作焦点；低档也必须能完成。

### C. 等春的年份 — 记忆花的两种开度

**位置**：倒影池旧台R `(-5, -29)`，沿A—R固定侧路可达。M台原本的主线保形投影保留；R台是可停留对照、由玩家决定定格的支线，不抢主线信息的首次展示。

**玩家做什么**：在明确标注“旧日影迹”的小花上调开合。先后看过两个极端，各停留0.65秒，顺序不限：闭合区`b<0.15`，开放区`b>0.85`。完成对照后，把花留在`0.35≤b≤0.65`的任一中间态，按“留住这一刻”保存自己的取景。这里的开度独立于主花和P1。

**对照证据**：

- 闭合：外侧年轮继续经过，内圈记录停住；穿行标记绕过中心，在壳内留下受遮护的绿色幼芽，幼芽不被判定为死亡。旧记意向：“先让它们活过这场风。”
- 开放：花芯与幼芽露出，内圈重新流动，穿行标记接通中心，表现保形与外界联系的改变。这是抽象的旧日对照装置，不是当前玩家正在伤害幼芽。旧记意向：“等风停了，请记得把花再打开。”
- 中间定格：保留幼芽与空隙，同时让内外联系维持在玩家选择的程度。不是证明“半开永远最正确”，而是玩家为这两段互相牵制的事实选了一个可回看的位置。

本轮闭/开静帧已能辨认幼芽、内外圈与形态差别，普通输入检查已验证需看齐两面才能保存；静帧不能证明首次玩家理解“保护与停滞”，年轮动态与无需文字的可读性仍须连续观察。离开支线后定格姿态与重放序章演员隔离的新增回归尚未纳入当前26项报告。

**奖励**：`story.branches.memory=true`；`story.memoryBloom`保存0.35–0.65内的选值，R台持续显示这朵小投影，终章回信提及“你留下的开度”。不给第三种资源，也不解锁替玩家免除取舍的第四结局。

**容错**：可反复开合，无倒计时；没有看齐两面时保存按钮说明缺哪面。同一游戏会话内退出面板保留两面已观察的标志，重新进入不必重演全部；跨刷新保留需要落实下节的可选字段。因为R台固定，任何时刻都不会改动正在承托玩家的桥/叶道。

## 6. 数据、输入和存档契约

与主控约定的持久化字段为：

```js
story: {
  introSeen: false,
  branches: { rhythm: false, light: false, memory: false },
  motif: [0, 0, 0, 0, 0, 0],       // 0停顿、1左杯、2右杯
  lightFound: [false, false, false],
  memoryBloom: 0.5
}
```

记忆对照的“已经看过闭合/开放”可增加经明确校验的布尔字段，也可以作为支线会话状态：若当前版本不持久化，界面必须告知“离开后可重新对照”，不能宣称已保存。需要完整分次体验时推荐`story.memorySeen={closed:false,open:false}`，由主控在落地时确认字段名。

所有新字段均有旧存档默认值。读取只允许白名单布尔、六个0/1/2整数和有限范围数字；坏的支线字段不能把有效主线存档整份清空。只接受用户明确按“留在这里/留住这一刻”的操作写入完成状态；照光的三个局部发现可以逐步保存。

输入优先级：全屏/设置/模态UI → 引言推进/跳过 → 当前支线 → 当前主线聚焦 → 漫游。进入支线时清空按键、停用主花排斥与世界拖动。Esc退出当前支线，退出后不会继续播放未完成的声音队列；对话聚焦在滑杆上时Esc仍有效。键盘等价动作在面板旁明确显示。

幕间字幕通过事件发送一次，不每帧覆盖；重复聚焦只显示该节点的简短提示。用存档已有进度推导主线事实，不因重载再次声称“第一次看见”。

## 7. 三种结局与支线回信

三种组合仍保留不同代价，绝不新增“全做完支线就得到最佳结局”。结尾只追加玩家实际完成的细节，最多三句，不能替未做的操作编造经历。

|组合|标题|主回信|可停留的最后画面|
|---|---|---|---|
|记忆＋四季|旧灯与新芽|“旧雨声有了可以重听的地方，新的芽在它旁边长起来。这一程，向远方的播种暂缓；这里先成为一个能继续生活的家。”|旧杯记录与新花的节律并置；远航杯保留空位，已有问候灯不熄灭。|
|记忆＋远方|把故乡寄给远方|“旧灯仍亮，种子沿航道启程。本地花庭暂时停留在这一季；你把保存下来的生活，送去新的地方。”|完整旧片段可重播，真实播种种子越出穹顶；本地现有生命继续存在。|
|四季＋远方|春天不只一种形状|“眼前开始长出新的四季，远方也收到种子。旧日留下可触碰的形体与零散声纹；完整重现，暂时留在花里。”|新芽与远景脉冲同时继续；两杯可由玩家亲手敲响，不能自动冒出未获种核的完整旧回放。|

条件追加句，可直接拷用：

```js
const BRANCH_REPLIES = {
  rhythm: '你把自己的六拍杯声，留在那张没有写名字的座位旁。',
  light: '你照亮的地址仍在：后来者有席，此处。',
  memory: '旧台上的花停在你留下的开度，保护与等待都没有被省去。'
};
```

共同收束句：“游絮停在你身旁，接出一声新的回应。春信写到这里，还留着空白。”这不强迫三结局使用完全同一动作时间；若杯声支线已完成，可播放玩家六拍后接游絮一声，否则使用已建立的三拍＋第四拍。

当memory用途未选中时，玩家自编杯声仍然可以播放：它是弥新写的短句，不是需要种核持续运行的完整旧日雨声回放。这样支线奖励不会偷渡终局代价。

## 8. 文案替换与演出验收

当前v3代码的`journal.table`把第三道水痕解释为“这里曾经有过第三个人”，应改成下列更精确的观察；`journal.echo`与`protocol`也可使用本版短稿，不能在尚未经历时直接开放全部解释。

```js
const JOURNAL_V4 = {
  table: ['没有写名字的杯', '桌边有两只杯子，水里却留着三道旧痕。第三处没有名字。刻字说，要给后来的人留一个位置；后来是否有人坐下，记录没有回答。'],
  leaf: ['半开的光', '花开到一半时，光从瓣间穿过，照见水下的旧路。完全开放也很美，却不能把这一束光留在同一个方向。'],
  echo: ['新的回应', '旧杯的回应是三拍。游絮却添了一拍，再自行停到另一处。它是眼前的新生命，不需要照着过去回答。'],
  protocol: ['等风停了以后', '保形协议曾让花庭活过风暴。风停以后，结构却仍守着原样。旧记录留下下一句话：请记得把花再打开。']
};
```

本轮验收不看文案“是否诗意”这一项就结束。至少做以下观察：

- 引言看完或跳过后，玩家能说清“我是新花灵/送春者、旧人只在记录里、现在先调眼前花”；角色页能补回跳过的信息。
- 开场的花与点云来自同一形体，相机没有丢方向，回到玩法没有重置用户当前进度。全屏进入/退出不影响引言计时或世界比例。
- 静音时，杯声六拍、旧三拍与游絮新回应仍由图形区分。键盘与触屏能够完成全部支线操作。
- 没做任意支线也能理解三用途和通关；做了支线之后，世界与回信至少各保留一处自己造成的变化。
- 玩家不会把R台旧风投影看成当前伤害生命，也不会把远方问候看成已完成播种。
- 不重复循环台词、不抢安全提示、不用计时等待拖长内容。48秒是可跳过的镜头编排，不计作强制游玩时间。
- 支线不会改变P3可达性、占用保护、种核数量、已提交结局或完整旧回放是否持续运行的边界。

## 9. 本次主动补充的第一方创作依据

检索与阅读日期：2026-11-18。以下是公开创作说明，作为方法研究，不将商业游戏的素材、声音或代码复制进项目，也不要求购买游戏来完成本次制作。

- **SEASON叙事设计师Meg Hutchison的创作说明（2022-06-02）**：记录工具让玩家取得环境的不同层次，并把自己的观察组织成可留下的表达。本作借鉴的是“操作产生个人痕迹”，转成可编排六拍杯声；不照搬其人物、旅程或世界观。来源：[开发者发表于PlayStation Blog的正文](https://blog.playstation.com/2022/06/02/discover-the-gameplay-and-story-of-season-a-letter-to-the-future/)。
- **Jusant开发团队的无对白叙事说明（2023-06-12）**：空间遗存、日常用品、同伴的互助和声音主题共同传递关系。本作据此检查杯子、旧台、游絮是否真的参与动作与回应，避免一条“故事很深”的标签替代体验。来源：[DON’T NOD团队发表于Xbox Wire的正文](https://news.xbox.com/en-us/2023/06/12/how-dont-nod-tells-an-emotional-story-without-words-in-jusant/)。

这里的具体六拍创作、三叶刻痕、旧花双开度对照与三种支线回信均为本项目原创设计。上述文章支持制作方法的选择，不证明本作已经达到其叙事效果；必须以新的实机与玩家理解验证。
