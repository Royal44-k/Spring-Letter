# 花与粒子游戏：可复用制作手册

2026-11-18｜从本次证据、设计与独立评审中沉淀。此处是项目知识档案，不代表模型永久学习、后台自动更新或技术效果已经实现。用户确认的边界：独立新主题，与金沙无关；舍弃付费方案。

## 1. 本次已经学到的具体内容

| 观察或核查 | 可复用结论 | 应避免的误判 |
|---|---|---|
| 百合在银、晶体、自然花之间切换 | 同一几何需要三套可信材料身份，先看不发光时的形体 | 只换颜色就称复刻 |
| 开合影响花瓣曲率，水面可独立触碰 | 把模型变形与环境交互分开实现，再统一输入 | 整体缩放假开花；UI拖动同时触发水波 |
| 粒子形变局部发生，未命中处保形 | 稳定表面身份、局部力场、阻尼回位优先于随机噪声 | 用随机星空替代有轮廓的点云 |
| 原片UI写出滚轮、拖动、排斥说明 | 高分辨率复核文字可纠正仅凭动画推测的输入 | 根据一个动作猜全部键位 |
| 全屏点场成因不明，FPS只有界面自报 | 区分画面事实、作者声称、实现假设和实测结果 | 把相机推近认成流体爆炸，把240K当已核实计数 |
| 新作需花→尘→花桥 | 同一可组合机制应有空间后果与失败恢复 | 两个漂亮Demo用转场拼接即宣称完成游戏 |
| 评审指出滑行可绕过花桥 | 先定义移动能力，再定义关卡的阻挡和解锁 | 角色无限飞行，却把地面桥当主线奖励 |
| 评审指出只有“归形”没有“散形”输入 | 视觉状态机必须给每条迁移定义输入、条件和中止 | 可逆承诺只写在渲染章节，玩家无法操作 |

## 2. 视频参考审查工作流

1. 保存文件位置、字节数、SHA-256、流信息和实际解码数量；保留原始文件不覆盖。
2. 按呈现顺序解码每帧，记录帧号和PTS。变帧率视频不得仅以“帧号/30”换算。
3. 输出全帧联系表，确保每帧在索引中；另输出固定间隔概览，帮助追踪完整节奏。
4. 通览所有联系表，对每种材质、输入说明、起止状态、极端形变和异常状态提取原分辨率帧。
5. 先记录“看见什么”，再写“可能如何实现”；统计中的UI、遮罩与加载转圈应单列。
6. 设计必须保留项、可改项和不确定项。缺少源站/源码时，不编造作者、框架和硬件。
7. 把参考锚点变成可操作的验收条目，见[视频矩阵F01–F08](video-analysis.md)。

本次实际完成：2629帧解码及数据、27张全帧表和12张概览表视觉通览、关键原尺寸帧复核。未完成：原音轨听审、源站实时输入记录、原作者代码/性能复现。

## 3. 建造配方：如何从观察走向实现

以下是设计阶段形成的配方；其中花体morph、同源采样、GPU粒子与输入路由已进入v3实现。具体完成度见[当前制作定稿](release-design-v3.md)及[开发记录](development-log.md)，技术依据和版本差异集中见[资源与架构](resources-architecture.md)。

### 花的连续开合

- 先做可绕视的花苞、中间态、盛放态。花瓣根部固定，尖端沿有方向的弧线运动；每个阶段检验厚度、法线和互相穿插。
- b∈[0,1]控制姿态，材质m独立。不要把滑杆进度同时当灯光、开度和粒子密度的唯一参数。
- 加入细微个体差异，但不让噪声改变解谜的目标开度。先关闭Bloom查看轮廓和高光，再追加效果。

### 表面粒子与回聚

- 粒子身份保持稳定：三角形ID＋重心坐标＋固定种子。当前目标由实际花开姿态求出，散形起点不落在旧的静态模型上。
- 可用弹性回位、阻尼、指针排斥和解析风场；先做到局部扰动、恢复可靠，再考虑复杂涡流。
- 跨对象映射预先按花瓣/躯干/翼片等结构分组，再处理内部空间对应。均匀随机重排容易制造穿心直线和无意义乱麻。
- 模拟位置与速度双缓冲。读取上一轮状态时不要误以为先注册速度计算就让位置自动获得本轮速度。
- 大多数视觉粒子不承担机关判定；用少量逻辑光团、接收范围与容差保证低档同样可玩。

### 明暗融合与输出

- 银花靠反射与虹彩，晶体靠透射和厚度，自然花靠花瓣与花芯层次。alpha透明不是折射，彩虹贴图不是薄膜虹彩。
- 实体淡出和粒子淡入共享进度，但曝光和发光能量单独调校；中段避免两者相加导致突然白屏。
- 水纹可以解析计算，焦散可以视觉近似；明确说明近似方法，不虚称完整物理求解。
- 数据纹理保持线性，颜色贴图标记sRGB，输出转换一次。渲染版本锁定，最新文档与本地API逐项核对。

## 4. 每次迭代的最小证据包

| 文件 | 最少内容 | 能证明什么 |
|---|---|---|
| 变更记录 | 本轮假设、改变、原因、剩余问题 | 为什么做这次修改 |
| 固定机位截图 | 同尺寸、同状态、同曝光，包含低档与无Bloom | 形体/材质是否改善 |
| 连续操作录像 | 普通输入、反向、失误恢复、结束状态 | 不是只挑最好的一帧 |
| 性能记录 | 设备、GPU、浏览器、分辨率、DPR、P50/P95、最坏转场 | 在哪些条件下达到目标 |
| 玩法观察 | 初次玩家行为、误解点、是否自助恢复、支路发现 | 美术是否支持而非遮住玩法 |
| 资源清单 | 来源、许可、修改、归属、下载日期、校验 | 是否可合法复用和再分发 |

推荐迭代顺序：一个问题→一个具体假设→一个可比较改动→同条件证据→保留或撤回。失败记录同样留存，避免下轮重复走弯路。不因构建成功而记录“视觉验收通过”。

## 6. 设计审查记录

2026-11-18第一次独立建造审查发现两项高优先级问题：移动能力可绕开桥、散形主动输入缺失。

v1.1处理：滑行依附相连承托面；Q连续散/收、Space向明确目标归形、Tab分配滚轮输入；提交前可逆，稳定完成后锁定通行结构。复查结论：两项规则缺口闭合，未发现新的重大冲突。此为文档逻辑评审，不能替代灰盒游玩或实机验证。

后续每轮追加：日期、证据位置、评审问题、采取行动、复查结果。不要把未执行的测试写进“通过”栏。

## 7. v2叙事与可玩性深化

用户要求宏大叙事、内涵情调、艺术交互与高可玩性。本轮据此修订主设计，具体规则见[体验蓝图](experience-blueprint.md)，公开第一方借鉴依据见[补充研究](research-depth.md)。没有重跑原视频并虚增帧审查次数，没有把文档推演称为游戏实机。

可复用的五条经验：

1. **先检查决策是否重复。** 调一个光接收器、调两个光接收器、调终章光接收器，视觉虽不同，仍可能是同一道题。本版分别改为观察、风场双解、材料调度与用途安排。
2. **宏大感需要可见联系。** 远景与主角的动作有响应，同一日常物件跨越时间形成意义；不用增加一整片可漫游世界也能建立尺度，但不能把装饰远景当作可探索承诺。
3. **艺术反馈同时帮助理解。** 水纹显出线索，撤力让生物自愿靠近，稳定ID让旧形态转成新路线。主题必须出现在操作因果里。
4. **可逆应细分对象与时刻。** 永久通路、临时结构、终章预演有不同生命周期，不能只写一句“全部可逆”。占用保护要覆盖依赖承托面，并禁止延迟排队拆桥。
5. **有后果不等于惩罚。** 三用途都值得保留，有限种核只限制新增的持续过程；既有生命和主线成果不被拿来要挟。后果先预演，提交明确，重演说明时间边界。

设计稿合并了叙事与系统两位审阅者的建议；原始notes文件是备选意见记录，实际建造以主提案和体验蓝图为准。高可玩性仍须正常输入、不同解法、异常恢复与首次玩家观察证明。

v2独立建造审查发现并修正三项因果缺口：预演不能提前产生不可撤回的播种；游絮新增一拍之前必须让旧三拍可辨认；保形的保护理由必须有主线可操作证据。复查通过，未发现剩余重大设计冲突。另对P3的4个安全台×4个材料形态做静态可达推演，16个状态均能通往所有安全台；两枚核心的13种合法分配包含3种用途组合。见[静态设计模型记录](design-state-audit.json)。此推演不包含连续变形、碰撞、保存时序或玩家体验，不是游戏测试结果。

## 8. v3实际制作：从“知道原理”到能被证据约束

本轮已进入独立代码制作。下面记录真正遇到的问题和采用的方法；正常输入完整通关与最终画面仍以[开发验收记录](development-log.md)为准，不因记录了经验就宣称永久学习或自动进化。

### GPU计算读的是上一轮，不是注册顺序

GPUComputationRenderer的变量依赖读取上一轮状态；先注册速度，再注册位置，不意味着位置会读取本轮新速度。设计积分时应明确 `position(t)`、`velocity(t)`和`target(t)`分别来自哪里，避免无意多出一帧延迟、振荡或两次时间步。数据纹理保持线性，不给位置／速度标sRGB。模拟步长有上限，后台回来不能补算数秒的巨大冲量。

本次把当前花开姿态直接映射到同一批真实三角采样目标；低密度回退保留相同表面身份。前端只检查WebGL2不够，还要验证实际浮点颜色缓冲支持，并在计算失败时给出有用的较低密度版本。能力回退成功也不代表它与GPU版已有相同运动质感，仍需比图与输入检查。

### 薄壳的法线不能只检查“数值有限”

最初几何测试能证明顶点与normal没有NaN，却未能发现花瓣薄壳上下表面朝向反了。独立检查后新增“同一薄壳上下成对法线朝外”的用例，先观察失败，再修正三角绕序。正确做法是同时验证顶点连续、拓扑一致、法线方向和透射用途；`computeVertexNormals()`不会替你纠正错误的三角绕序。

真实表面采样测试不能仅证明“固定随机种子每次相同”：还要把采样点投到实际闭合三角形上，取得重心坐标，再验证同样坐标能得到开放姿态点。这样才能捕获与可见网格不一致的漂亮假点云。花瓣开合使用position／normal morph，茎根不缩放；任何全株摆动要放在实体与点云共同的父变换中。

### 输入互斥要检查事件阶段与库内修饰键

Three r185的OrbitControls在`MOUSE.ROTATE + Shift`时会切换到平移；当`enablePan=false`，它直接不处理。仅在后注册的`pointerdown`里临时把LEFT改成ROTATE，不但顺序太晚，还会被Shift语义再次拦截。本轮改用捕获阶段决定操作归属，并使尘模式LEFT映射与库内Shift规则配合；花模式左拖、尘模式Shift拖、触屏单指分别处理。

检查清单应包括：按下、拖动、移出、抬起、取消、失焦和UI覆盖。镜头操作开始后要关闭粒子与水波输入；不能仅在右键分支排除，却漏掉左拖和触摸。关闭设置、退回扉页、切换鉴赏模式时清空按键和指针状态，避免返回后仍在移动。

### 真实GPU、SwiftShader与帧间隔是三种不同证据

浏览器成功启用WebGL并不证明正在用硬件GPU。无头运行可能选择SwiftShader；该结果适合检查编译、资源与交互错误，不能与AMD硬件的帧时放在同一条“优化前后”曲线上。性能记录必须包含渲染器字符串、硬件、浏览器、视口、DPR、画质、粒子数、测量路段和采样数。

早期AMD／1280首屏约16.7ms只是一轮初测。后来正式构建的1440×900尘鉴赏末段180帧记录为均值20.51ms、P99 25.9ms、最大28ms，平均约49fps；更完整的数据不能被较漂亮的早期首屏值替代。两者都不是GPU着色耗时，也不证明全部四幕稳定60fps。后续还需P50/P95、最坏转场和真实设备分档；没有GPU timer测量，就明确只报告浏览器帧间隔。

### 预演是可撤销的信息，提交是世界后果

核心分配状态与`ending`分开。局部花座可在预演时播放记忆、生长和航线投影；真正外发的飞种只读已提交结局。给两个花座分别高亮，不能等同于让玩家看见不同未来的局部后果；本轮因此补入三用途局部预演和M台保形证据。

重演也有生命周期：不能把“回到启程前”仅放进一次性结局弹窗。关闭弹窗、刷新、继续存档后仍需可见入口；提交前存档损坏时，应保留当前有效进度并解除提交状态，不能把有效通关存档换成全新开局。世界反馈、规则与存档测试必须覆盖同一边界。

### 多解与撤力不能只存在于说明文字

两条画出来的线不自动构成两种策略。当前P2已加入内外空间风强差异与周期安静窗口；“保持实体挡风花／散开后走短路”的更深环境改造仍未全部实现，文档须明确区分。成功接收也不能只判断“到达目标附近”：持续施力时禁止累计稳定停留，并要求撤力后的速度足够低。本轮新增了相应规则测试。

### 让知识成为可继续使用的制作档案

每个修复保留最少四项：具体触发、失败证据、代码／规则改变、同条件复查。来源资源同时保留原始URL、作者、精确许可、SHA和实际用途；本轮棚光还核对官方MD5并通过HDRLoader解码。候选石材、读过的示例与真正入包资产分列。网站可访问、代码可复用、资源可商用不是同一结论。

文档首页同样属于交付：当前名称和状态放在最前；原帧明确标参考，首版截图明确标实机；Markdown互链转HTML时只转换同一档案内确实生成的页面，不能把外部项目README错误改成不存在的README.html。链接检查证明可阅读，单元测试证明局部规则，普通输入与真实GPU记录证明对应运行条件；任何一项都不能代替其他项。


银材精修补记：明亮金属底层与过强白色clearcoat会遮住薄膜颜色，即使参数中`iridescence > 0`也可能只剩铬色。此次改用原创灰度UV膜厚图，保持线性数据，由物理薄膜shader随视角计算色彩；微调金属度、IOR与clearcoat，不绘制彩虹基础色。新增`setSurface`只更新现有材质的虹彩、膜厚、光泽和有限亮度，有限值检查须保留真实的0，忽略NaN／Infinity；切换材质恢复各自预设。两个新测试验证灰度厚度数据、几何／采样身份不变、边界钳制与自然花不染虹彩，完整单元套件升至33项通过。是否更接近原视频仍以重建后的固定机位截图决定。

## 9. v4：演出、存档与证据的边界

**证据绑定到构建和实际观察。** 保存报告时间、构建标识、普通输入范围、截图和失败项；分别记录“代码存在”“图像已见”“流程已过”“首次玩家理解”。新构建修了问题，只能先写“已修待复查”，不能沿用旧构建通过数。音频图没有泄漏不等于混音好听，平面反射出图不等于与原片水质一致；帧时最大值也不因平均值好看而省略。

**可重放演出读取剧情快照，独立安排演员。** 序章可以让弥在出生位置表演，但不能临时改玩家的持久坐标或关卡状态再希望稍后恢复。镜头、演出角色、临时花开度和字幕属于展示状态；真实位置、已保存杯曲、已定格记忆花、种核分配属于存档。重看从结局开始、途中跳过、失焦、退出支线时，分别验证展示退场与存档未变。已保存旧花姿态在离开交互后还须由持久值驱动，不能继续引用已清空的面板草稿。

**新增支线入口不能盖住已有收集入口。** 当杯桌、旧记录和支线共享空间或E键时，按玩家当前距离、焦点与可见提示决定入口；完成支线之后仍要能够访问旧收集和重听内容。回归要从正常行走/按键到达，覆盖完成前后、返回旧场景与刷新存档。进入另一支线时清理上一条临时字幕，避免正确的存档逻辑配上错误的叙事声部。
