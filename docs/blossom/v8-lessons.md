# 春信 0.6：本轮留下的设计与工程经验

2026-11-21。依据本轮代码、隔离浏览器普通输入和同版本运行记录整理。这里记录可以再次采用的方法，以及它们不能替代的验证。

## 让花尘成为行动的一部分

上一轮的花朵散聚和追风能展示效果，但缺少贯穿全程的具体需要。本轮用三封旧来信把行动串起来：读到愿望、接通叶脉、决定照料对象、看见变化、写出回信。雨庭建立分流，风庭增加止漏，潮庭要求双源汇合。新增内容需要改变玩家的判断，不能只改变粒子数量、颜色或任务名字。

源花的展开、散开、流动、归形在同一个空间发生；流路由规则判定驱动。接通先预览，回信才保存。这样的区别让玩家有尝试和反悔的余地，也让视觉变化有可读的原因。两种照料给予同等行路能力，避免所谓情感选择实际变成挑数值奖励。

这解释了本轮设计取舍，不能证明玩家已经觉得有趣。下一条证据应来自陌生玩家能否看懂、主动继续、记住自己照料过什么。

## 下一步必须落实到真实空间

完成一个机关之后，需要的是具体去处，而不只是“已完成”的提示。三庭共用下一程判定；第三封回信把目标交给旧石台和织桥。导航沿实际可走陆路找下一段，不用穿越水面的直线箭头误导玩家。主动追踪已回信的庭院有明确优先权，自动主线不能每帧把它改回去。

手机标题保留寄信人与愿望，点石方法保持可见；详细原文和更多操作可以折叠。回信后同时出现一句结果和下一程按钮，让玩家不必在长文字里找出口。近看棋盘时收起人物和同伴，保持可点击区域与视觉位置一致。

实现位置：`letter-ui.js` 的 `letterNextStep`、`letter-controller.js` 的显式追踪、`letter-wayfinding.js` 的实际地面路径。最终路线记录见 [冻结候选证据索引](../../spring-letter/evidence/v8/release-evidence.json)。

## 玩家进度先落盘，演出再承认成功

新旅途、导入、寄出与回退都可能覆盖投入。先生成独立候选，验证并保存成功，再改变正在运行的状态和播放“寄出”的演出。预览、取消、配额失败、损坏、未来版本和多标签冲突需要不同处理，不能一律变成新档。

聚合存档是权威来源；旧键用于迁移与兼容。固定备份保护重开之前的旅途，滚动恢复点保护最近有效保存。导出应能救回当前页尚未写入的旅途，不能悄悄拼入另一标签页的结尾。`localStorage` 检查不等于真正跨页面原子锁，仍须保留冲突出口。

显式临时模式是一条恢复路径，不是保存成功的替代说法。界面一直说明它只在当前页内存，并提供导出。

## 减少等待，先找同步成本

颜色切换不应重新生成两份未改变的几何采样。当前花型有界缓存保留抽样元数据，只重算颜色，并用旧数组哈希确保优化没有悄悄降低效果。独立 CPU 对照见 [采样性能记录](v8-performance.md)；它不能代替浏览器首帧与 GPU 性能。

首屏只准备当下花色，其他材质首次选择时再准备，并显示明确过渡。异步编译期间必须及时恢复渲染目标；不能把临时离屏状态悬置在 `await` 两侧，让正常动画绘制到错误缓冲。首次选择的等待和后续缓存命中分别记录，不用缓存后的快速启动冒充冷启动。

反复进入同一阶段时比较几何、纹理、程序和音频节点的数量，避免把正常的首次预热当泄漏，也避免只看某一帧占用就宣称长期稳定。

## 声音要从实际动作验证

七种真实乐器采样演奏原创乐段，草地、石路、鸟和河声来自登记过的 CC0 原件。调度随庭院与状态改变；潮庭旧曲同拍、新声迟半拍，保持同一动机和音量基础，让差异来自回应方式。

首次脚步的问题来自触发节奏：长按会响，短促但有意的移动却可能完全无声。本轮加入首次落脚准备和音频时钟限频，再验证短按、连续移动与松手停止。界面显示“音·开”不证明真正输出，所以从游戏自己的 AudioContext 录制并解码，检查静音、电平、暂停时钟和资源上限。

[实录与分析](../../spring-letter/evidence/v8-audio/actual-analysis.md)只证明录制路线实际发生了什么。没有人工听审就不写“音乐好听”；没有录到的潮庭分支或可选追风也不能借这段录音声称听感通过。

## 交付测试过的那一套字节

每个候选使用独立目录，记录输入和产物哈希。全流程、触屏、视觉、声音、存档、持续运行都指向同一入口；发行只复制已测产物，不临时重新构建。旧包和失败证据保留。

一次回归遇到运行环境中断，记录了约 72 分钟的单帧间隔和导航超时。这不是正常游玩帧率证据；保留被污染记录，原样重跑。不能删掉失败后声称从未失败，也不能把宿主暂停当成玩家的持续卡顿结论。

桌面包与网页包分别解压、逐文件散列和 HTTP 验证。网页入口在 ZIP 根部，所有资源相对解析；本机启动器明确检查 Node。制作机通过不等于干净 Windows 或真实手机全部通过。

## 下一轮应先做什么

先实施 [8–12 人观察方案](v8-product-release.md)，记录无需讲解的首庭完成、阻塞原因、继续意愿和选择记忆。没有真实购买行为，就只称受众与商业模式假设。

工程上继续覆盖一般运行异常的统一恢复出口、可调文字与阅读停留、真实触屏设备的性能和操作。艺术上继续打磨人物表演、场景生活痕迹、音画节奏与材质层次；优先根据真实停留和困惑处改动，不把更多机关和更大地图本身当作成熟度。
