## 2. ShiningBlossom：花的材质与生长是主角

录屏中可辨标题为 **STILL / BLOOM — Lilium**。品牌与源站作者尚未独立定位；不能把搜索到的同名字体、艺术录像当作原站。下述时间是本地视频时间，边界由联系表与放大帧观察，动作起止约有数帧不确定性。

| 时间 / 帧 | 画面事实 | 设计含义 |
|---|---|---|
| 0–0.63s / 0–19 | 淡紫明亮展厅、右侧拱门、左上薄纱，液银虹彩百合已盛放；水面反射与明亮网状纹理 | 花并非普通发光网格，形体依靠轮廓、曲率、高光与环境反射共同成立 |
| 约0.67–1.0s / 20–30 | 已开放花瓣收为细长花苞，底部BLOOM进度变化 | 必须支持连续、可逆开合；不可用整体缩放替代花瓣卷曲 |
| 2.4s / 72 | 背景与UI切到深紫夜间；花和场地保持 | 同一空间的昼夜表现，不是切换一张背景图 |
| 约3.8–5.2s / 114–156 | 花苞展开，花口逐步张开，仍有未开的花苞 | 不同花头错落与阶段差异形成自然节奏 |
| 约6–7.7s / 180–231 | 花的虹彩和高光变化，镜头/主体持续转向 | 材质受视角、光照影响；不能把彩虹固定贴在屏幕上 |
| 约8.03–8.73s / 241–262 | 材质菜单出现，选中Sculpted crystal，背景被模糊 | 这里的模糊明确与菜单遮罩同时出现，不能一概当成场景景深 |
| 约8.8–18s / 264–540 | 晶体表面保留厚度、透光与色散观感；指针在水面附近，出现移动涟漪与局部光斑 | 水面有独立交互价值，浅水焦散应与花的细节分层 |
| 约18.03–19s / 541–570 | 快速收拢后重新展开 | 需要检验中途反向拖动不会跳帧、翻面或穿插 |
| 20.8s / 624 | 选择Lily后变为橙黄花瓣、绿色茎叶 | 自然花、液银花、晶体花是三套材质身份，不能只换基础颜色 |
| 21.9s / 657 | 同一自然花切回浅色白昼空间 | 明暗两套环境都要能读清自然材质 |
| 23.2s / 696、约27.5s / 825 | 切为粉白，再回到橙黄 | Blush/Golden属于自然花变体，可成为游戏内审美奖励 |
| 32.53s之后 / 976起 | 画面整体变暗并出现加载转圈 | 这是录屏内可见状态，原因未知；不列为期望艺术效果 |

### 可读到的交互契约

原分辨率第0帧的底部说明明确为 **Scroll to bloom · Drag to rotate · Skim or tap the water**。底部还有播放/回置、BUD—FULL BLOOM连续滑杆、Material、Auto-rotate、Chase light；右上是Day/Night切换。只看到入口不证明每种组合都已实际被录制。

材质菜单的三个类别：

- **Liquid silver**：液态铬感与薄膜虹彩，表面控制包含Iridescence、Film thickness、Gloss、Radiance。第0帧显示36%、325nm、81%、28%，这些是界面显示值，**不是可直接移植的Three.js参数**。
- **Sculpted crystal**：圆润厚度、折射光；控制可见Fire、Refraction、Gloss、Radiance。需要保留内部透光与外部高光的差别。
- **Lily**：自然缎面花瓣，Blush/Golden两变体，控制包含Gloss、Petal sheen。

### 必须保留与可以重设计

必须保留：细长茎叶与多花头轮廓、逐瓣连续开合、三种材质差异、虹彩随视角变化、浅水涟漪/焦散、柔和明暗环境、近距离旋转观察。可调整：具体配色、展厅建筑、界面排版、标题、花头摆位、控制项命名。参考的极小文字和大片高亮不应照搬到实际游戏可读性上。

## 3. 3D粒子效果：有形体记忆的点场

原分辨率标题可辨为 **XIAMI / BEYOND THE SCREEN**，不是早期缩略图可能误读的KIAMI。主体是具有帽子、眼镜、身体及底座轮廓的卡通人物点云；新游戏拟采用原创花灵替换人物，保留点场视觉与响应特征。人物具体身份与原资产许可未核定。

| 时间 / 帧 | 画面事实 | 应保留的效果 |
|---|---|---|
| 0–2.2s / 0–66 | 黑底、大量细点组成可辨认的立体表面；顶部粉紫，底部蓝紫，微弱背景晕光 | 粒子首先构成有层次的形体，不能替换成随机屏幕星空 |
| 约2.23–6.53s / 67–196 | 下部、头部局部被拉伸/推开，出现薄片状流线，随后回到人物轮廓；部分时刻明显旋转或放大 | 局部作用、连续位移、恢复形体；形变期间仍有未扰动区域 |
| 约6.57–11.7s / 197–351 | 主体由模糊团扩展为覆盖大部分画面的点场 | 满屏空间感值得保留；单看录像无法区分粒子扩散、相机靠近、点尺寸及景深各自贡献 |
| 约11.8–20s / 354–600 | 点场收束成粉蓝双团，身体细节渐渐清楚；中途仍可被扰动 | 恢复不是瞬间切回完整模型，应先形成整体质量分布，再显出细节 |
| 约20.77–21.3s / 623–639 | 左侧标题与导航渐退，保留更纯净的互动舞台 | 从介绍页进入沉浸操作时可渐隐UI，主体空间连续 |
| 约23.8–28.3s / 714–849 | 第二次出现满屏点场 | 可重复的状态变化，比只播放一次入场动画更有互动潜力 |
| 约28.5–35.5s / 855–1065 | 再次渐聚并恢复轮廓 | 必须能多次扰动、恢复且不积累漂移 |
| 约36–40s / 1080–1200 | 局部卷动，主体仍在暗场内 | 回聚后保留呼吸感，不应完全冻结 |
| 约41.1–41.5s / 1233–1245 | 标题导航返回 | 展示/沉浸状态可逆，不通过重载网页恢复 |
| 41.5–52.53s / 1245–1576 | 点云继续轻微转向/局部扰动 | 静止观察也需细微生命感，避免全屏噪声持续抢注意力 |

### 可读到的交互契约与限制

第0帧右下有 **SHIFT + DRAG · ROTATE / SCROLL · ZOOM**。第640帧沉浸态下方可见 **MOVE TO REPULSE**，支持“移动指针产生排斥”这一交互意图；回聚速度、力场半径、按键细节与深度映射仍未获源码确认。右下显示约118 FPS及240K，**仅为录屏界面自报**：视频自身30fps，无法验证真实渲染帧率、硬件或粒子总数。

画面呈现的是点云/粒子表面，不能仅凭外观认定使用了Gaussian Splatting、流体仿真或某种GPGPU实现。新方案将明确选择可控的表面采样＋力场回位算法。

## 4. 融合原则：同一物体的三种状态

1. 实体花：可观察曲率、材质与连续开合，承担近景审美和可理解的机关形状。
2. 花尘：沿当前花瓣表面采样，受到指针、风与水波影响；开花与散开是两个独立参数。
3. 重凝：同一批稳定粒子回到明确的花瓣、花灵或路径目标；大形先成立，细点再收稳。

主画面常态由花与空间构图主导，粒子只在玩家操作和剧情节点升强。暗场用于读点云，亮场用于读材质；两者之间通过世界内灯光、相机位置和局部环境变化衔接。不能在两个独立Demo页面之间跳转后称为融合。
