附录：初始化计时与首帧基线复核

旧构建 /assets/index-DOLalDHR.js 的长跑证据记录了累计 longestMs=9088.3、over1000=1；读取的首个 silver 和末个采样均保持这两个值。该累计指标受到初始化预热计时污染，不能解释为已可交互阶段停顿九秒。

  • 预热调用的 raw=0、dt=0、世界时间保持 0，帧计数不增加。

原问题是输入事件与 RAF 频率不同：main 每帧按当前位置差分计算速度，没有新 pointermove 的帧立即得到零速度，随后把散尘目标清零。受力向量先限幅又丢掉了稀疏事件所累计的路程。受控 CPU 样本在 60 Hz RAF / 20 Hz 输入下得到 18,0,0 的速度和 1,0,0 的目标，最终散尘约在 0.3125–0.3547 波动；末端平滑本身不能恢复连续笔速。这解释了快扫仍保留大量实体的状态，不是缺少固定散尘动画。

  • Red：可导入、确实执行旧单帧限幅行为的 helper，在同一测试文件下 10 项中 7 项断言失败、3 项通过，进程退出码 1；失败不是 import 错误。Green：修复后完整 npm test 100/100 通过，包含 helper 的 10 项测试。
