# V11 花桥绿色波浪墙审查

日期：2026-11-23。范围：花桥构造期间出现的绿色遮挡；本记录区分几何证据与后续实机视觉验收。

## 根因

`spring-letter/src/world.js` 原有 `shieldSail` 是一块人为建模的连续曲面：宽 3.9 米、高 2.3 米，以正弦函数形成波浪，初始高度 0.05 米；旋转后位于约 (-3.25, 0, -30.7)。它被挂入 `shieldRM`，使用与绿色叶渡共用的双面材质。玩家建造 `shield_rm` 时整组可见，0.7 秒显现动画将共用材质的不透明度从 0.22 提到 1。因此玩家看到的是完整的绿色波浪墙，而不是粒子故障或上一版的 NaN 全屏故障。静态批处理把这块曲面并入叶渡网格，更容易在一般场景树审查中遗漏它。

旧注释称其为侧面柔软防护，但它既没有独立低透明度材质，也未注册到镜头遮挡避让名单；注释与实际效果不符。

## 修复

删除这一块过时的竖向装饰曲面，保留 R↔M 的低矮叶片渡路、通行支撑、显现过程及存档键 `shield_rm` / `leaf_rm`。A↔M、M↔F 的花桥形态与控制保持不变。不通过改绿色色值或隐藏全部叶渡来掩盖问题。

父任务需将仍在 `index.html` 的可见标签“风屏 · 旧台 ↔ 中庭”改为“叶渡 · 旧台 ↔ 中庭”；内部存档键应保留兼容性。

## 可重复证据

新测试 `spring-letter/tests/bridge-presentation.test.js` 真实创建 `createWorld()`、让与花桥无关的开场光圈结束，比较建造前后实际可见网格，并在静态批处理后检查每个顶点的世界坐标：

- 修复前：A↔M、M↔F 通过；R↔M 失败，实际新增几何最高点为 **2.350 米**。
- 修复后：三条渡路均低于 **0.4 米**，连续 21 个取样点仍有通行支撑，显现完成后仍有可见实体。
- 初版测试曾把开场瞬态光圈混入新增对象集合，造成两个无关失败；已通过等待光圈结束后再取基线消除该测试问题。没有把该初版输出算作根因证据。
- 聚焦桥梁、手势、地形与资源释放的测试：**17/17** 通过。
- 全部现有 Node 测试：**481/481** 通过，日志 `spring-letter/evidence/v11/bridge-full-suite.log`。世界资源释放原有测试同时验证几何与材质只释放一次。

## 同类排查与实际体验验收

检查了三条可变渡路、开场布帘、风庭独立风帆、潮汐织信背景幕。开场布帘仅宽 0.56 米、透明度 0.38，且 `depthWrite:false`；风庭三面纱帆分散在 x≈10–15 的景观区；潮汐帷幕是独立交互的受控背景。未发现它们重复“低矮桥与竖向墙共用最终变不透明的显现材质”这一根因。三条渡路的新增几何高度回归测试可防止把类似墙体重新静态合并进去。

实机视觉验证交由父任务统一执行，避免多个 GPU 测试并发互相干扰。复现路径：完成风廊后，从 A 台沿侧路走到 R(-5,-29)，向 M(0,-32) 织出 `shield_rm`，观察建造前、显现中、显现完成及行走过桥时的画面。旧版生产服务可用于修复前截图，新版开发/候选服务用于修复后。CPU 几何证据不能替代这一实机检查，也不代表新海上章节已验收。
