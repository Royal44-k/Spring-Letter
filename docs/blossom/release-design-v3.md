## 2. 主题：让被保存的故乡，再次拥有未来

迁徙方舟曾把故乡的季节写进花朵。漫长风暴里，“保形协议”让生命和生活片段免于散失，也让四季停在同一个春天。玩家是一枚刚醒来的花灵：最初希望补全旧日的回答，后来发现眼前的新生命并不需要成为过去的复制品。

宏大世界通过**季节档案、方舟、远方节点和播种航路**建立联系；情感从**桌边两只杯子、三道旧水痕、游絮多出来的第四拍**进入。每完成一项操作，远方关系改变一点，近处日常也多一层意义。没有以毁掉已有生命换取结局的道德考试；最后两枚种核选择的是继续支持哪两种未来。

视角由浅水里的杯纹进入花冠，又从花冠望向星岸；主题落在动作里：留一点含蓄，光才穿过花瓣；收回持续的推力，游光才自己停下；先让自己站稳，才能重新借出同一份材料；明确启程，预演才成为世界的后果。

## 3. 四幕与操作的艺术因果

| 幕／空间 | 玩家真正做的决定 | 可见反馈与意义 | 首版实现与剩余验收 |
| --- | --- | --- | --- |
| Ⅰ 栖光庭：半开的故乡 | 观察线索，把花停在约45%–60%的开度，并维持0.8秒 | 花瓣让光通过；水下旧路变为可走通路，旧杯纹开始可读 | 正常滑杆操作解锁已通过；杯纹节律与叙事提示的艺术可读性继续精修 |
| Ⅱ 风织廊：风中的回信 | 选择更安稳的外侧长路，或等内侧短路的横风转弱；从侧后方推光，末段撤力 | 路线长度、风场和操作窗口形成真实差异；放手后才稳定接收，同伴接出新回应 | 已补空间风场差异与撤力／低速停留条件；正常指针送达已通过；双路线全面抽样与初次玩家理解继续检查 |
| Ⅲ 倒影池：借一段花桥 | 一份花尘只维持一处结构；在固定石台更换桥或风屏，安排去路与返程 | 材料的旧形态成为新连接；M台保形投影呈现“当年保护／如今停滞”的因果 | 正式输入验证桥上拒绝回收且不排队、第二桥抵达彼岸；M台交互投影已补，艺术可读性待查 |
| Ⅳ 初绽穹顶：待寄出的春信 | 把两枚种核分配给记忆、四季、远方三个用途中的两个；比较局部预演，再主动启程 | 本地记忆、眼前生长、远航投影各有状态；提交后只持续激活被选择的用途 | 局部预演与提交边界已补；三种结局、重复分配拒绝、重载与回看已通过，最终视觉继续精修 |

P2首版采用**空间风强差异＋周期窗口**实现两路，不等同于v2设想的“玩家散开挡风花、主动重排遮风环境”全部完成。该进一步策略仍列入精修项，不能把两条装饰线当作多解，也不能把当前较小的差异扩大宣传。

主线采用 WASD／方向键移动、E靠近细看、滚轮或滑杆开合、Q花尘散聚、结构按钮／空格归形；设置中提供返回安全台。鉴赏台分别保留花朵旋转与粒子观察：花模式拖动环看、滚轮开合；尘模式移动排斥、Shift拖动环看、滚轮靠近。相机手势与排斥、水波互斥；详细实际按键以游戏内当前提示为准。

## 4. 两段视频怎样融合，而不是并排播放

核心结构是**同一株花、同一张表面、同一批有身份的粒子**。实体花瓣的闭合／开放网格决定粒子的两个目标姿态；每个粒子保持同一三角面和重心坐标，当前开度在两姿态间连续插值。材质可换，点位不随机重置；中途散开、回收、反向开花不会换成另一团无关星光。

在主线上，花瓣决定光与风，花尘表达回流和材料重组；少量确定的逻辑光团负责谜题，视觉粒子负责形态和触感。桥的可走状态由规则系统确认，不能因为视觉粒子短暂散开就把玩家丢进水里。

## 6. 免费制作路线与实际采用资产

首版采用本地 **Three.js 0.185.0、WebGL2、Vite、Web Audio**；测试采用Node与已有Playwright。原创参数花瓣、茎叶、程序材质、场景几何、合成声音和视觉近似共同建立风格。没有付费生成API、订阅素材、会员提示词或运行时素材站依赖。

实际下载并入库的外部美术资产是 [Poly Haven Studio Small 09](https://polyhaven.com/a/studio_small_09)，作者 **Sergej Majboroda**，**CC0-1.0**：1024×512 Radiance HDR，1,615,248字节，用于花材的柔光箱环境反射。MD5与官方API一致；本地HDRLoader解码成功；[出处记录](../../spring-letter/public/assets/environment/studio_small_09_1k.source.json)包含SHA-256和许可链接。它不被误称为原创摄影。

[免费资源清单](free-assets-v3.md)还核查了ambientCG浅色石材与Three.js开源曲面、物理材质、GPU计算、表面采样和水波示例。**候选不等于已入包**：未采用的石材不计入成品资产；示例代码的MIT不自动覆盖其所有附属模型和贴图。

模型和游戏判定分开：花体的13个网格约4.95万顶点、9.68万三角；标准粒子目标为65,536粒，降级减少密度而保留稳定表面身份。上述是当前模块规模，不是总场景预算或性能保证。优先减次要背景、分辨率和后期，不能靠删除谜题逻辑让低档“流畅”。

## 7. Fable案例：把传播口号变成可检验的生产方法

Saltline是与描述最接近的候选，但没有用户看到的原片，不能唯一确认。资料已分出首次无人反馈artifact、后续改进artifact及非官方镜像；普通请求虽有HTTP 200，实际返回地域不可用页面，因此没有伪称实玩了原版。制作时长、费用和token数字仍按作者转述／镜像证据标记，不能当作本项目成本或工期保证。

可迁移的做法是：**空间集中、视觉高密度、模块化实现、持续迭代、独立审图、普通输入验收、保存完整证据**。一句提示是输入入口，不意味着瞬间完成、免费获得同等计算量，或已经达到商业AAA完整度。Graveyard Shift的作者仓库为模块化制作与打包提供了另一条一手实现依据；本项目不复制Saltline镜像的整段代码、关卡或资产。详见[版本与证据核查](fps-case-v3.md)。

## 8. 制作优先级与首版明确差距

| 优先级 | 必须收敛的内容 | 通过标准／当前边界 |
| --- | --- | --- |
| P0 正常操作闭环 | 四幕路径、两路P2、P3占用保护、三种结局、恢复与回看 | 16项浏览器检查覆盖正常输入全流程、三结局与重载回看；8项边界检查通过；无隐藏状态修改推进主线 |
| P0 形体与交互一致 | 同源花尘、可逆开合、局部排斥、输入互斥 | 同机位对照参考与实机；反向／重复操作无漂移；最终视觉待验收 |
| P1 材质与场景层次 | 银花宽高光、晶体厚度、自然花细脉、薄纱与浅水 | 当前实机仍需控制亮部、提升近景材质层次和花形精度；不把强光当电影质感 |
| P1 叙事可读性 | 三拍／第四拍、M台保形证据、三用途预演 | 让玩家从空间和反馈读懂，而非主要依赖长说明；新增投影已写，画面仍待检查 |
| P1 性能与生命周期 | 真实GPU、最密状态、后台暂停、重载、损坏存档 | 正式构建1440×900尘鉴赏末段180帧：均值20.51ms、P99 25.9ms、最大28ms；尚非全场景、GPU timer或多设备结论 |
| P2 进一步可玩性 | P2主动遮风重排、更丰富支路／声纹编排、摄影与触屏细化 | v2完整愿景，未把首版程序写入当成这些内容全部完成 |

完整精修篇章的30–45分钟仍是设计目标；首版实际时长没有完成记录，不能靠拖长步行或重复机关凑数。尚不声称电影级渲染、商业AAA质量、像素级复刻、多设备全面兼容或首次玩家测试通过。

实际性能记录来自AMD Radeon Graphics经ANGLE／D3D11硬件渲染，在1440×900的尘鉴赏模式末段采样180帧，标准GPU粒子为256²＝65,536：帧间隔均值20.51ms、P99为25.9ms、最大28ms。该段平均水平约49fps，不能宣传为“全游戏稳定60fps”；1280首屏约16.7ms的早期结果也不能替代它。GPU着色器耗时、完整四幕最坏转场、其他DPR与真实手机数据尚未齐全。

边界检查明确覆盖损坏JSON安全开局、禁用localStorage仍可玩、blur清空移动、低档实际128²计算纹理、Shift旋转、滑杆焦点下Esc退出、上下文丢失后的恢复提示，以及仿真触屏完成P1。边界测试会主动注入浏览器故障夹具，但主线通关只使用普通键鼠／UI输入；这两类测试不能混称为完全相同条件。

## 9. 发布前证据与下一轮知识沉淀

正常输入全流程已留证据；最后的美术验收仍需要同一版本的六组画面：入口构图、银花近景、晶体侧光、自然花细节、局部粒子扰动、终章预演／提交后差别；已通过的操作范围见两份JSON；还需用最新精修版本补齐连续镜头、失误、反向和全部视觉状态的可比证据。新截图不能覆盖参考原帧而失去对照来源。

本轮已沉淀到[制作手册](knowledge-playbook.md)的具体经验包括：GPU变量读取上一轮状态；曲面薄壳法线必须朝外；OrbitControls的Shift语义与事件注册顺序；真实GPU与SwiftShader数据不得混用；预演与提交分离；规则测试通过不能证明画面或玩法已经成熟。后续以“问题→改动→同条件证据→剩余差距”继续追加，形成可复用的制作档案。
