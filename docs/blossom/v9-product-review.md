# 《花漾年华：待寄出的春信》0.7 产品复盘

记录时间：2026-11-21。`v9` 是本轮工作记录编号，游戏包版本为 `0.7.0`。本文依据本轮源码、已有截图和[一手案例研究](<D:/AI Game/docs/blossom/v9-interaction-research.md>)，不把源码存在、自动化操作或截图完整等同于真人觉得好玩。最终构建、操作回归、性能与音频验收由主任务另行补充，本文不填 QA 通过数。

## 这轮解决的产品问题

用户连续指出：三个庭院虽然题面不同，仍然都是转动石片、接通流路、选择一个出口。操作节奏、空间构图和反馈基本相同，导致旅途像展示品。这个问题不能用更多花色、更多按钮、更多粒子数量来补偿。

本轮把三个新玩法接入现有主流程：**摆放花影 → 连续渡风 → 编排春声**。保留参考花卉与花尘作为视觉和材料线索，后续行动围绕禾、阿渡、岑的记录与游絮展开。本作保持独立主题，没有把金沙的人物、文物或叙事加入新章节。

当前更准确的产品定位是：**已有三种不同操作、个人作品留存和主流程连接的浏览器艺术探索版本**。它尚不能凭模块数量、代码规模或一次顺利操作被称为成熟商业游戏，更不能称为已达到电影或 AAA 制作水准。

## 已实现的差异与明确取舍

| 体验 | 当前源码支持的行为 | 与旧转轮的实质差异 | 仍然有限的地方 |
|---|---|---|---|
| 花光暗房 | 连续抓取和移动三片玻璃花笺；投影随位置移动；按形状接近幕上轮廓；撤回、取消、键盘微调；逐层生长；提交后树影与新花改变植物大小、聚集位置和投影重点 | 玩家观察前后图层与连续位置，手直接推动物件；不用离散旋转或端口连通 | 三片各有作者设定目标与容差，属于有限空间谜题。没有任意光线追踪、自由摄影造景或多解几何系统；不能宣传为无限创作 |
| 纸翼渡风 | 自动向前航行，玩家连续控制横向与升降；惯性、上升气流、侧风、椭圆/菱形风门、缓行；偏航后回到安全风段，已过风门保留 | 关注速度、轨迹与空间预判，输入需要持续调节；失败恢复进入下一次尝试，不是复位三个转轮 | 当前是编排好的五道风门，并非开放世界自由飞行；完整历史轨迹没有写入作品存档。安全恢复是否仍有张力，需要真人验证 |
| 回声织信 | 三种声源、八拍布尔谱面；逐点编排、拖奏、删除、撤回与试听；至少三个音符、两种声源，完整听过当前版本后可以提交 | 从寻找标准答案切换为选择声音与留白；提交的是玩家实际安排 | 音阶和拍位有限，不能改任意音高、时值或速度；不等于完整作曲软件、录音工具或在线生成音乐。满足最低条件不证明创作过程本身令人投入 |

实现依据：[花光暗房](<D:/AI Game/spring-letter/src/moment-rain.js>)、[纸翼渡风](<D:/AI Game/spring-letter/src/moment-wind.js>)、[回声织信](<D:/AI Game/spring-letter/src/moment-tide.js>)。

节奏目标是让注意力经历“观察—行动—表达”的变化。三个章节共享进入、退出、提示、存档和回信的外壳，但没有再抽象成同一套转子模型。共享 UI 有维护价值，也有使体验继续显得相似的风险；真正的差异要由场景里的物体响应来承担。

本轮继续采用 Three.js 与原创程序几何，复用既有声音系统，没有购买游戏、模型、音轨或付费生成服务。这样能把工程投入集中到输入、状态与美术反馈；代价是角色表演、复杂材质、环境密度与叙事演出依然受当前内容规模约束。

## 主线替换与旧旅途的边界

当前 [main.js](<D:/AI Game/spring-letter/src/main.js>) 引入新的 [moments-controller.js](<D:/AI Game/spring-letter/src/moments-controller.js>)，三个新模块成为来信互动入口。旧转轮规则仍留在仓库中用于兼容与既有数据，不应把“旧文件存在”解释成用户必须再做一遍旧三庭。

存档采用两层记录：

- 旧 `letters` 继续保存选择、阅读状态和原有回信。对于已经回信且没有 `edition: 2` 的旧记录，`momentLetter()` 返回原有文字；不会悄悄将“浇老树”的历史改写成“拼花窗”。
- 新 `moments` 单独记录草稿和完成状态。旧回信没有被直接转换成“已玩过新玩法”。未回信的条目显示当前新内容。
- 只有用户在新玩法中完成并提交，才写入 `edition: 2` 与 `artwork`。提交先构造候选状态并保存，保存成功后才替换当前状态和演出回信。
- 恢复旧档的代码保留原选择与旧旅途进展；这不是对所有历史浏览器、所有异常存储介质作出零风险保证。最终兼容验证记录需与发布构建对应。

依据：[旧来信恢复](<D:/AI Game/spring-letter/src/letter-model.js>)、[新体验状态和文案选择](<D:/AI Game/spring-letter/src/moments-state.js>)、`main.js` 中 `commitMoment()`。

## 个人作品现在留下了什么

[作品留影模块](<D:/AI Game/spring-letter/src/moment-keepsake.js>) 根据已提交的 `entry.artwork` 生成 SVG，并由来信册和结局展示。旧档或不合法的数据返回空串，不用一张预制作品替玩家补历史。

- **花光**：图中使用三片花笺保存时的实际位置，并按树影/新花选择留下不同意象。它记录的是有限谜题内的摆放与选择，不应夸大为自由绘画作品。
- **纸翼**：展示配置中的五扇沿途风门、已通过标记和保存时纸翼位置；图中明确不表示完整个人飞行轨迹。当前没有足够数据重建玩家每次转向。
- **春声**：八朵花的成对花瓣逐格对应真实三声部、八拍音符，未选的位置仍是留白，没有硬编码统一“优秀作品”。

来信册的“收藏这一页”在本机导出 SVG，不会替用户对外发布。分享价值目前是一个待观察的产品假设。

[score-preview.js](<D:/AI Game/spring-letter/src/score-preview.js>) 从保存的谱面生成实际乐器事件，使用与创作关一致的声源、音高和拍位；[main.js](<D:/AI Game/spring-letter/src/main.js>) 把事件送入音频引擎，并按 `data-keepsake-beat` 高亮花谱。它具备真实回放的代码路径，不是把“播放”按钮连到固定 BGM。关闭、失焦等路径调用停止逻辑。这里记录实现事实，不替代最终听感、静音状态、尾音与取消操作的实机验收。

## 从成熟作品中真正留下的经验

研究区分了作品事实与本项目推论。本轮没有复制这些作品的角色、画面、音乐或完整机关。

- 从 [Viewfinder 开发者文章](https://blog.playstation.com/2023/06/08/create-destroy-and-rewind-in-viewfinder-out-july-18-play-the-demo-today/) 采用“可靠回退降低实验顾虑”的原则，落到暗房撤回和飞行安全风段；没有声称实现照片改变任意三维世界。
- 从 [Chicory 开发者文章](https://blog.playstation.com/2021/03/17/the-world-is-your-canvas-in-chicory-a-colorful-tale-coming-to-ps5-and-ps4-this-spring/) 采用“作品属于玩家、提示不只依赖颜色”的原则，落到形状线索与真实乐谱留存。
- 从 [Jusant 的攀登设计说明](https://dont-nod.com/en/scaling-new-heights-learn-more-about-jusants-innovative-climbing-system/) 采用身体操作、环境影响和安全恢复共同形成节奏的原则，落到持续调节纸翼；没有搬来绳索攀爬引擎。
- 从 [SEASON 的开发者介绍](https://blog.playstation.com/2022/06/02/discover-the-gameplay-and-story-of-season-a-letter-to-the-future/) 采用记录可以回看、回听并承载意义的原则，落到图谱与谱面回放。记录如何影响后续人物关系，仍有深化空间。

研究文档中的所有提案并未全部实现。例如开放式多路线飞行、同伴在后续情境中重新使用玩家记录、完整旅途轨迹等，不应因研究里写过就进入功能宣传。

## 商业价值仍有哪些待证问题

可探索的方向是：愿意短时停留、享受美术与轻度操作、愿意表达和保存个人作品的玩家。浏览器入口、三个不同动作和可带走的图谱，可能形成清楚的体验理由。但这只是定位假设，不是已经找到用户群体的结论。

仍缺少以下真实证据：

- **体验理由**：玩家是否会因第一眼的花卉与光影留下来，并认为后续操作配得上这个期待。
- **可消费内容**：真人自然完成时长、哪些地方主动停留、哪些地方只是在找按钮；不能把拖延或迷路算成内容时长。
- **复玩理由**：固定暗房和固定风门是否有值得再次尝试的变化；乐谱是否足够有表现空间，而非随便点三下交差。
- **情感记忆**：玩家是否记得禾为什么等春天、阿渡为什么需要纸翼，以及游絮的回应与旧记录有什么关系。
- **作品价值**：玩家能否认出自己的摆放与声音，是否愿意主动收藏、再听或展示。导出功能存在不等于分享意愿存在。
- **商业可交付性**：跨设备稳定性、可访问性、内容维护成本、可扩展章节质量，以及实际愿付费的理由均未得到充分证据。不能填造销量、市场规模、留存或付费转化数字。

一个可操作、可保存的版本是必要条件。成熟度还要求稳定的体验承诺、足够的内容变化、可信的视听质量和被目标玩家认可的价值。现阶段应让真人观察决定下一笔投入，而不是继续用更多模块证明规模。

## 截图审读：唯一最高优先视觉与 UX 建议

本次审读以下已生成图像，均为时间截面的画面证据，不证明操作通过率，也未必覆盖主任务随后修正：

- [1440×900 花光暗房](<D:/AI Game/spring-letter/evidence/v9/visual-2026-11-21T07-34-16-719Z/1440x900-rain.png>)：细框、透光片、幕布暗边和植物已经区别于早期彩色卡片；但面板的面积和信息量仍比场景动作更抢眼。
- [390×844 回声织信](<D:/AI Game/spring-letter/evidence/v9/visual-2026-11-21T07-34-16-719Z/390x844-tide.png>)：乐器可以分出层次，底部面板占据较大纵向区域；截图本身不足以证明小目标的触摸命中是否轻松。
- [844×390 纸翼渡风](<D:/AI Game/spring-letter/evidence/v9/visual-2026-11-21T07-34-16-719Z/844x390-wind.png>)：主体缩到画面上方很小的一块，底部面板接近占去半屏，上方可见直立背景板边缘。纸翼和当前风门难以从这张图中辨读，容易继续呈现“远处展示品”的感觉。

**最高优先建议：先确保主动作拥有足够大的有效视口，再安排操作面板。** 横屏采用可折叠的紧凑操作条，把人物引言和详细规则放到展开区；根据收起/展开后的实际可用区域重算构图。飞行时优先看到纸翼、下一道门和风向变化，停止后再容纳较完整的故事文字。

可采用本项目自己的验收目标：在 844×390 下，正常游玩状态无需滚动即可到达关键操作；下一道门的开口和纸翼能在正常观看距离清楚分辨；面板展开不会使已经抓住的对象失踪。以上是拟议目标，不是引用的行业标准或已完成结论。应先解决这个问题，再追加装饰粒子或更多景物。

## 下一轮小规模试玩：六个可证伪问题

建议先观察 6–8 位未参与开发的人，包含至少两种输入方式。先让他们自然操作，再询问原因；不提前解释谜底，不以“觉得很美吗”一类引导问题取代行为证据。下表是预先提出的失败信号，不是现有测试结果，小样本也不能用于估算商业转化率。

| 待验证问题 | 如何观察 | 什么结果会推翻当前设计判断 |
|---|---|---|
| 1. 第一个动作是否可以理解？ | 初次进入暗房，不口头教学；记录首次有目的的拖动、是否看见影子对应关系、首次求助发生点。可把 45 秒作为观察节点，而非倒计时压力 | 两位以上参与者仍只在面板试按钮、看不出可抓对象，或把投影变化理解成随机反馈：应重做物体可操作线索与首屏构图 |
| 2. 偏航后的恢复是否让人愿意再试？ | 观察第一次自然错过风门后，是否明白回到了哪里、已过内容是否保留、是否主动使用缓行或调整路线 | 多位参与者把安全返回理解为程序故障或全程重置，或退出的理由是无法判断下一次如何改：恢复机制还没有被正确传达 |
| 3. 三幕是否真的被体验成三种行动？ | 结束后请玩家不用界面名称，分别描述自己刚才做了什么；结合输入轨迹和停留位置 | 玩家仍统一描述为“点按钮等完成”，或主要时间用于面板操作而非场景行动：机制虽不同，呈现与引导仍把它们压成同一种体验 |
| 4. 春声是否让人拥有作者感？ | 请玩家找到刚才留下的一处留白或音符，在来信册回听，再自行决定是否修改 | 多位玩家认不出自己的声音，认为回放是预制曲，或只为最低通关条件随便点选且完全不愿改动：个人作品价值尚未成立 |
| 5. 选择是否与人物和世界有关？ | 不重读长文，让玩家说明一位寄信者需要什么，并指出树影/新花选择在场景里的差异 | 玩家只能复述“完成三个小游戏”，说不出角色需要，或看不出选择带来的生长差异：叙事仍主要停在说明文字里 |
| 6. 通关以后是否有自发留下的理由？ | 给出几分钟自由时间，观察是否主动重飞、改谱、回听、收藏一页，或直接退出；记录选择原因 | 没有人愿意做任何延伸行为，或收藏只是研究者提醒后的礼貌动作：不能宣称已经具备复玩或分享价值。无需要求参与者对外发送作品 |

记录应保留失败尝试、误解原话和未被完成的任务。下一轮优先修复反复出现的阻碍，再决定增加内容、扩大受众测试或讨论收费形式。截图、自动化回归和真实玩家观察分别回答不同问题，应分别保存证据。
