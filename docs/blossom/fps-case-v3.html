Fable 5.2 射击游戏案例：从传播口号到可复用制作方法

更新日期：2026-11-18。服务于《花漾年华：待寄出的春信》；独立于金沙项目。

本轮是对 research-cases.md 的补充核查，重点是 Saltline 的版本溯源、制作证据与可执行验收。未运行任何外部游戏代码，未购买模型、素材或服务。这里的开发建议是本项目的工作方法，不等于已经完成的开发或测试结果。

1. 这轮真正新增的结论

  1. Saltline 仍是最接近用户所述传播案例的候选。 Fable 5.2 的模型名称与官方发布信息已在前报告核实；本轮不把它误改成其他模型。没有用户看到的原传播片段，不能唯一认定案例身份。
  2. 必须区分最初无人反馈版与后续改进版。 公开出处整理同时列出两个不同 artifact，并转述后续约两小时的武器、声音与玩法改进。前报告把当前版称为“原始作品地址”，应改成“当前公开版地址”。这一版本线索可靠到可以保留，但本轮未能读取官方作品内容，不能把改进时长升级为独立验证。
  3. 可借鉴的是“小场景、高密度、长时间自主迭代”的生产方式。 “一句提示”描述输入入口，不能代表一次推理、瞬间生成、零成本或无需验收。
  4. 单文件是交付方式，不必成为开发架构。 另一位作者公开的 Graveyard Shift 已有模块化源码、构建、测试与质量分档，再打包成 HTML。它给本作的工程启发，比强行把所有逻辑写进一个文件更直接。作者仓库

以下证据等级贯穿全文：A＝本次直接读到的一手文档或作者仓库；B＝直接检查到的第三方副本，原版一致性未证实；C＝链接回作者的转述，原始内容本次不可读；D＝为本项目提出的方法或推论。

5. 第二个第一方案例：Graveyard Shift

这说明近期不止一个 Fable 5.2 FPS 在传播，但还不足以判断用户看到的究竟是哪一个。作者的 发布帖 自述约 14 小时、消耗约 120% 周额度，并使用多个模型协作；加载图来自图像生成。这是作者报告，未复核调用账单。

作者仓库 可直接读到：Three.js/WebGL2、设备质量分档、程序生成模型/纹理/音频；加载图与分享图是例外；源码分为规则、场景、材质、导航、音频、渲染等模块；esbuild 输出单 HTML；包含烟雾检查和截图脚本；标示 MIT。可选排行榜后端与核心游戏分离。这些是一手公开实现说明，不是本轮实测性能。当前仓库经过多少次生成与人工修改，也不能仅凭成品倒推出“一次完成”。

对本作最有价值的组合：模块化制作、程序化统一美术、可关闭的非核心联网功能、离线可审查的交付产物。 宏大叙事可以靠世界关系与后果展开；第一章的空间仍应集中，以保证每处都值得探索。

6. 可以直接移植的生产方法

6.1 先把“小范围但高密度”转为本作约束

首个可玩章节围绕一个能反复改变状态的主场景展开：信庭、花体与通往远方的粒子信路彼此连通。主花承担近景材质与散聚的视觉要求；周围空间承担探索、谜题和叙事反馈。玩家每完成一次行动，至少改变一个可见状态，而不是只增加任务计数。

暂不以铺大地图证明宏大：先做出“玩家能让一座空间从封存走向回应”的完整因果，再以远景、回信、不同年代的遗物展开更大世界。这是 D 级设计建议，不是 Saltline 已实现的玩法。

6.2 程序化资产服务统一质感

对两段参考视频中的共同对象建立同一个几何来源：花瓣表面采样点、完整花瓣网格和散开后的粒子共享稳定 ID 与目标位置。这样“凝聚成花—触碰散开—引导归位”可以是连续状态，而非两种互不相关的特效切换。

把花瓣曲率、层数、薄膜色、粗糙度、粒子密度、散开半径、恢复阻尼做成参数；固定随机种子。每次调色不重新随机造型，每次材质修正都能与同一镜头比对。新增免费素材应逐个记录原始来源、许可证、用途与本地转换；网页展示免费不等于素材可任意再分发。

程序生成解决的是风格一致与可调节性，不保证自动达到高质量。主花、手边交互物、地面水光与远景必须分别校验形体、材质和光照，不能用强泛光掩盖模型问题。

6.3 使用独立视觉审查，但给它正确的输入

Saltline 制作视频里的“第二模型看截图评分”目前只读到了 二手报道，不能写成亲眼验证。更明确的一手依据是 Abyssal Garden 的 公开 prompt.txt：它直接要求独立审查者只看渲染结果，使用六个固定机位与运动录屏，并记录平均、P99 和最大帧时间。原提示词指定的高端显卡与分辨率不可直接作为本机性能承诺。

本作采用两轮审查，防止“符合参考”与“本身好看”互相替代：

  • 参考一致性审查： 输入相应参考帧、对应游戏截图与相同时间段录屏；检查花型、空间层次、粒子尺度、散聚节奏和交互响应。屏幕录像看不到的内部逻辑标为推断，不捏造原实现。
  • 独立艺术审查： 只看本作截图和短录屏，不看代码与作者解释；检查焦点、明暗层级、材质可读性、操作反馈、眩光、闪烁、穿插和镜头舒适度。

审查发现使用同一格式：截图/时间码 → 具体位置 → 观察到的问题 → 对体验的影响 → 最小修正 → 同机位复查结果。例如“00:12 花瓣边缘过曝，银白花瓣变成一片白，细层无法读出；先下调 bloom 阈值之外的贡献并恢复局部对比，再复查”，而不是“画面不够高级”。

7. 本作首个章节的具体验收办法

以下是建议的验收目标，尚未经过本机实测，不是已经达标的结果。

检查固定条件与记录通过依据
六个视觉机位入口远景、银白花体近景、晶体/薄膜侧光、粒子局部排斥、信路形成、结尾回信；固定镜头与随机种子主体轮廓、材质、密度和景深层次可辨；关键参考帧各有对应；没有主花穿插、大片过曝等重大缺陷
散聚连续性同一花体连续 20 次散开/归位，记录首尾与中间状态无粒子突然换位、永久丢失、越操作越漂移；重新开始可恢复初态
交互响应按下、拖动、离开、松开、取消、失焦逐一检查；降低帧率再试行为可预期，无卡住的“按下”状态；操作造成的变化可见且可逆
完整玩法新存档按正常操作走到结尾，覆盖至少一次误操作、重试、暂停与继续不依靠隐藏测试按钮；有探索线索、可判断的解法、完成反馈和可抵达结局
三种节奏自由探索、明确谜题、短时动态交互分别记录一个片段不能全部退化为寻找发光点后点一下；不同动作改变不同世界状态
运动画面固定 60 秒镜头路线，含转向、近景穿行、最密粒子与恢复无明显闪烁、几何跳变、粒子突然弹出；静帧美观不能替代此项
性能先记录真实硬件、浏览器、分辨率与画质；报告平均/P99/最大帧时间，区分 CPU 帧间隔与 GPU 测量高档以 60 fps 为目标；达不到时按数据降低粒子/分辨率/后期，并保留形态与交互；没有 GPU 测量就明确标记未测
本地完整性检查首开、刷新、字体/材质加载、断网与许可证清单核心章节不依赖付费 API；第三方免费资源可以追溯；无未说明的外部游戏代码

“六机位”“20 次”“60 秒”是可重复的抽样协议，不是全部缺陷已被穷尽的保证。审查者未发现问题也不自动意味着达到了电影或商业 AAA 作品水平。

8. 建议执行顺序与本轮资料边界

  1. 把两段视频的时间码、目标帧与可见交互转成对照清单，分开写观察事实、推断和主动改编。
  2. 完成主花材质与同源粒子散聚；用固定镜头证明它们能连续融合。
  3. 加入一条完整的“发现—理解—操作—世界改变—收到回应”玩法链，再加入不同类型的互动。
  4. 用六个机位与 60 秒录屏做艺术审查；先修会破坏视觉承诺和操作理解的问题。
  5. 在真实设备记录性能并设置分档；保持统一形态，按成本顺序降低次要效果。
  6. 留存参数、截图、问题清单、版本与素材来源，作为下个章节可继续使用的知识，而非一段无法复现的聊天结论。

本轮没有读到 Felix 的完整原始对话、原始调用日志、完整账单，也没有实玩 Saltline 或 Graveyard Shift；制作补充视频未直接观看。未找到可将两版 Saltline 与镜像逐字对应的官方校验值。这些缺口不会妨碍采用其可核查的制作思想，但不应被包装为已经完成的一手复现。
