# 春信 v9：把交互差异做进玩家的手里

研究日期：2026-11-21，北京时间。任务边界：《花漾年华：待寄出的春信》是独立项目，与金沙无关。本记录采用八个已发行作品的开发商、发行商、官方平台页面及开发者署名文章；不以商店宣传证明本作会有同样品质或市场表现。研究没有购买作品、付费课程或素材，没有把它们的截图、模型、音轨或角色下载进游戏。

本文区分三层：**作品可核实的事实**、**从事实提炼的设计判断**、**给本作的待实现提案**。阅读网页与公开创作文章不等于实际完整通关这些作品。侧边浏览器打开状态由主任务另行记录；这里提供已核实可读的一手网址。

## 先明确上一版为什么重复

源码中的三个 `LETTERS` 都落在同一 `tilePorts → evaluateLetter → rotateLetter → commitGardenLetter` 结构：点击石片、旋转离散方向、等流路接通、选两个出口之一。分流、避漏和双源确实改变了规则，但手的动作、视线位置、棋盘构图、成功演出和回信面板高度相同。用户感到“都是转轮取水”，是合理的体验判断，不能用参数不同反驳。

旧 `exploration-model.js` 另有沿圈描画、牵引种子穿三门、靠近花铃停听。它们也不能直接改名后声称已经交付全新章节。需要改变的是：**玩家需要关注什么、身体怎样行动、物件怎样回应、完成后世界有什么不可互换的变化。**

## 三条比宣传页更具体的开发经验

**给实验一个可靠的回退出口。** Viewfinder 的联合创始人 Gwen Foster 解释：放照片会覆盖旧空间，可能删掉关卡出口；团队加入回溯，目的是鼓励尝试，避免把整关重置变成负担。可提炼为本作的原则：新玩法的撤销、取消、离开、重新摆放必须成立，失败不擦掉先前的观察或创作。本作不需要复制完整时间逆行引擎。[开发者原文](https://blog.playstation.com/2023/06/08/create-destroy-and-rewind-in-viewfinder-out-july-18-play-the-demo-today/)

**给艺术表达留下非标准答案。** Chicory 的导演 Greg Lobanov 说明，玩家创作和装饰会持续留在世界中，支线创作还能改变其他角色聚集的位置；作品同时为解谜、慢慢绘画及需要引导的人保留不同选择，而且谜题不依赖辨别颜色。可提炼为本作的原则：创作奖励不应依赖“画得像”，颜色之外仍有形状、位置、声音与文字反馈。[开发者原文](https://blog.playstation.com/2021/03/17/the-world-is-your-canvas-in-chicory-a-colorful-tale-coming-to-ps5-and-ps4-this-spring/)

**把同伴做进因果。** Jusant 的创意总监说明，双扳机与手臂对应，绳索/岩钉建立安全恢复点，同伴能唤醒植物、揭示道路；不同群落的阳光、风和生物会改变攀登条件。这给本作的启发是：同伴需要有玩家不能独自完成的可理解作用，并在行动中表现关系；仅仅跟随、发光和弹一句旁白不够。[开发团队原文](https://dont-nod.com/en/scaling-new-heights-learn-more-about-jusants-innovative-climbing-system/)

补充：SEASON 的叙事设计师 Meg Hutchison 介绍了定向录音、回放与记录册，以及把记录展示给角色以获得信息或连接。本作可以学习“记录改变下一次相遇”，不需要立即开发自由摄影、音频编辑和全套手账软件。[开发者原文](https://blog.playstation.com/2022/06/02/discover-the-gameplay-and-story-of-season-a-letter-to-the-future/)

## 三种真正不同的关卡提案

以下是为现有 Three.js 浏览器项目拟定的原创提案，不是已实现的功能。取舍优先级是少而完整：三个不同的注意力模型、一条连续旅途、各自有可感知后果。不要用新增菜单项、清单或三个不同名字的进度条充当差异。

### 第一段：花光暗房——观察、拿起、摆放，发现一个不可能的春天

禾留下的是一座漏了雨的种子温室。花并非缺少一瓢水，而是被同一片温室玻璃隔绝在不同的季节。玩家先看到一片花影随手中的透光花瓣移动，再尝试将透明花瓣放在不同的光窗前。真实的前后遮挡、透叠关系和形状会改变影子，合适的空间关系使不同种子醒来。

- **手的动作**：近距离抓取、拖动、放置；走近不同观察位置。键盘可选物件并按方向键细移，避免只有精细鼠标才能完成。
- **判断**：观察光影的构图与植物反馈，判断哪个物件/位置能回应线索；没有石槽、转子或端口连接。
- **第一层反馈**：拿起时影子立即脱离原位，错放仍有真实可见结果；花叶朝光、透明花瓣边缘的颜色变化告诉玩家接近了。
- **惊喜**：本以为只是一张影子，完成后影子中的花从地面长成立体结构；同一片花瓣可以留在另一位置，形成玩家自己的窗景。
- **低风险实现范围**：使用作者事先设计的若干可移动花瓣、投影平面与受光区域，不做任意照片切割几何；有效摆放区有磁吸但不自动解题。仅投影/几何真实对应后才使用“影子成花”的宣传措辞。
- **叙事结果**：玩家替禾留下一个适合新生命的环境。信中记住实际留下的构图/植物，而不是统一“浇水成功”。

### 第二段：纸翼渡风——连续操控、借风、保护一封信抵达

阿渡的渡口是有高差、风向和遮蔽物的空中航道。玩家把第一段收下的花瓣折成短程纸翼，亲自操控它载着春信渡过裂隙。顺风推升，背风可休息；纸翼在树梢、帆影与水面之间变化高度，视差和景深让移动本身有乐趣。

- **手的动作**：连续控制升降和横向轨迹，按住展开借风，松开收翼减速；触屏保留方向区与明确的展翼按钮。
- **判断**：观察风中飘带、落叶和纸翼倾角，选择安全慢路或更有表现力的上升气流；不再搜集一圈同样的花灵。
- **第一层反馈**：输入马上改变翼面、尾迹和镜头偏移；接近危险时羽片卷起、音色收紧。偏航可以回到最近的风巢，已完成的段落保留。
- **同伴职责**：游絮提前轻触下一阵气流，使风向可见；玩家决定是否跟随，不能由同伴自动驾驶完成。
- **惊喜**：去程从桥下穿行，回望时发现自己的尾迹被沿岸植物记住，形成新的花带；抵达后阿渡的帆或迎客灯真实改变空间。
- **低风险实现范围**：一个明确边界的作者编排航段，有2–3个安全节点和两条可读路线，不做开放世界飞行模拟；相机跟随真实位置，支持轻缓动态，失败不坠落几十秒。用运动回归检查碰撞与返回点，不能靠传送脚本充当普通操作通关。

### 第三段：回声织信——倾听、选择、编排，让新生命回答

岑留下的并不是待修理的水路，而是一段缺少回应的旧声。玩家在潮边收听几种具有明确来源的声音：杯沿、纸页、花铃、游絮。把想保留的声音安放在水面不同的位置和时序，再让游絮唱出回应。这里从“判断一个正确答案”转为“做出自己的安排”。

- **手的动作**：点击试听、拖放声音位置/次序、按住形成长音、回放和撤销；不要求乐理、绝对音感或精确节拍。
- **判断**：决定保留哪些声部、哪里留白、让谁先回答。有限而和谐的音阶/节拍约束保证任意尝试都可听，不以评价“音乐好坏”作为通关条件。
- **第一层反馈**：每个声音对应形状不同的水面纹理与空间位置；静音时也可从脉冲长度、方向、字幕看懂。演奏过程中身体、相机和环境一起回应，而非只点菜单听短音效。
- **惊喜**：游絮没有复读旧曲，而在玩家留下的空隙添一声；这段实际编排在回程经过花带时再次出现，并进入最终春信的可重放记录。
- **低风险实现范围**：有限声部、固定最大事件数、可恢复的编排数据；使用现有免费许可乐器和原创动机，不采集麦克风、不调用在线生成音乐。声音真正由玩家事件回放，不能只换一段预设BGM后声称个人创作。
- **叙事结果**：玩家认识到保存故乡不等于让所有生命重复旧人的生活。高潮由操作完成这层含义，不依赖最后一屏长文解释。

## 为什么这不是三个换皮小游戏

| 维度 | 花光暗房 | 纸翼渡风 | 回声织信 |
|---|---|---|---|
| 主要注意力 | 观察关系与空间构图 | 身体轨迹与环境风力 | 听辨、安排与留白 |
| 主要输入 | 拿起、拖放、走位 | 连续方向与展收翼 | 试听、编排、回放 |
| 状态变化 | 物件位置/投影/生长 | 位置/速度/气流/安全节点 | 声部/时序/长度/个人乐句 |
| 成功解释 | 植物回应适合的光景 | 信和纸翼实际抵达 | 完成一段属于自己的回应 |
| 空间构图 | 近景透明温室，侧向光 | 开阔高差航道，动态视差 | 静谧潮台，环绕声与水纹 |
| 错误恢复 | 拿回与撤销 | 最近风巢安全返回 | 改编、静音预览与撤销 |
| 个人痕迹 | 留下的窗景/花形 | 经过的花带/抵达方式 | 实际乐句与空白 |

共同线索应是**花的物质状态改变作用**：透光的花瓣成为布景，轻盈的花瓣成为载体，散开的花尘成为声音的可见痕迹。每一段得到的东西在下一段有一次新用途，而不是三个章节各填一格。

不建议同时保留旧三转轮作为新主线门槛；新章节不能要求玩家先把被批评的内容做一遍。旧存档要迁移、备份，并明确哪些新体验尚未完成；不能伪造玩家已经玩过新玩法，也不能抹去已有春信。

## 艺术方向与节奏

《春信》需要自己的空间语法。建议减少各地重复的大金色拱环和相同圆形岛台，将材质与轮廓分成透光玻璃/湿叶、纸翼/织帆、夜潮/瓷杯三组；连接它们的是同一种花的生命与人留下的生活痕迹，不是古迹博物馆的陈列秩序。

首段以手边小变化吸引观察；中段释放速度和远景；尾段收束为倾听和个人表达。每段都包含可短暂停留的细节，但不堆相同收集物。惊喜按“熟悉物件 → 新作用 → 环境回应 → 后来再遇见”铺开，不靠频繁白闪、镜头旋转和旁白告知“这很震撼”。

首页参考花与粒子保留作为艺术母题。进入游戏时，花尘的颜色、运动方向和声音应自然把视线带向第一件可拿起的物件。让开场展示真正教会玩家观察和尝试，而不是先看一段与玩法无关的效果演示，再切成三张一样的棋盘。

## 实施与验收约束

1. 先做三个可操控灰盒并逐一通过输入、失败恢复和相机检查，再补完材质与演出。美术不能隐藏“其实又在点同一个按钮”。
2. 第一段让玩家亲眼看到一次错误摆放仍有可理解结果；第二段确认松手/切菜单立即停止残留输入；第三段确认实际个人事件回放而非固定曲目。
3. 面板只保留当前行动，操作说明随情景出现；读信不长期占据四分之一画面。原文可随时再看，但玩家的视线应回到物件、身体和环境。
4. 暂停冻结模拟与音频调度；中途退出、重开、旧档迁移、导出/导入继续沿用已建立的保存保护，新增瞬态速度不直接恢复成危险状态。
5. 三段分别保留普通输入证据，并检查曾经成功之后回访、不同完成顺序允许的边界、视觉质量、实际音频输出和触屏可操作性。不可用注入完成状态掩盖不能玩的关卡。
6. 最后让陌生玩家分别用一句话描述三段“我在做什么”；如果仍都回答“转东西让它亮”，说明设计差异没有成功呈现。自动测试只能证明规则与恢复，不能替代这条体验判断。

本研究不承诺这些提案已经实装，也不把三个小时的工作量等同商业大作制作规模。它给当前实现提供明确的替换方向：**三个不同的行动模型、一个能相互呼应的主题、可恢复的尝试，以及可被用户实际感知的变化。**
