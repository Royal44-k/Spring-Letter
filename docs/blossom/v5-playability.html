先把借鉴转成可执行判断

以下来自开发者、发行商的公开文字与页面，不是亲自试玩结论；网页和宣传材料也不能证明实际帧率或手感。本轮未购买游戏、素材、订阅或插件，未提取任何案例的美术资产。

一手案例实际核实到的设计本作采用的方法本作需要自己解决的问题
Sword of the Sea，创意总监 Matt Nava，2025-06-04开发者把移动放在核心；恢复海洋会让遗迹、鱼群、海带等环境与运动机会发生变化。到达与操作本身有反馈；完成一封信后，整座庭院开花、浮游种群恢复，返程也能看见成果。浏览器中的镜头、路面高度、手势占用必须共同验证，不能只摆出宏大景观。
Europa，发行商 Future Friends Games 官方资料2024-10-11 发售；在失落文明的遗迹中探索，以逐渐增强的移动能力连接景观、谜题与关于人和自然的故事。每座庭院放在主路可望见、需要绕行的侧路，环境解释“为什么走过去”，而不是任务清单替玩家决定一切。当前章节不冒充开放世界，也不塞入未实现的飞行系统；先让三个真实地点各有不同的动作。
Flower，thatgamecompany 官方页面玩家引导运动方向、聚集花瓣；收集行为改变环境。输入直接作用于世界中的花瓣/种子，操作和视觉回报共用同一对象；花庭恢复成为空间记忆。避免把“花”仅作为发光按钮。画环需要连续空间轨迹，种子需要运动路径与松手时机。
Samorost 3，Amanita Design 官方页面探索、谜题、奇异生物及魔笛贯穿九个世界；官方强调美术、声音与音乐共同构成体验。声音是找路线索，停步是一种有意义的操作。所有回声均有可见花铃与波纹，静音也能完成。不复制魔笛或谜题；用“收起风笔，给来信留一点安静”的动作承载本作主题。

这些参考说明的是方法，不构成“一句话即可得到 3A 成品”的证据。质量必须落到可操作、可恢复、可读、可测试的现场行为上。

三座庭院：一次旅程，三种关系

角色在主线中为失联文明递送春信。三座侧庭把宏观灾后重建落到具体关系：允许世界变化、给予而不占有、倾听而不替别人回答。文字只在动作后出现一句，剩下由场景承担。

地点与到达条件玩家看到什么亲手完成什么困难与软退可见结果与重演
雨留庭，(-12,-1)，高 1.6，初始可达半径 1.28 的十二枚悬花围成缺色花环；环中央是一封尚未展开的光信按住空格使用风笔，沿花环连续描一圈。任意方向均可；经过的花逐枚打开静止点按、隔空操作、大幅跳点不计连续画迹。短暂停笔可接续；长时间离开笔迹才慢慢退去庭院外围常驻花簇与浮游种群恢复；继续描画能重演和鸣，永久成果保留
风过庭，(12,-16)，高 2.5，第一幕开路后可达一枚有惯性的种子、三道依次亮起的风门、中央可辨认的乱流石用风笔吸引种子，绕外侧过三门；抵达花巢后松开风笔，让种子停稳顺序错误不会跳关；碰乱流被温和推回。越界回上一道门，不清除已走过的路。仍抓着种子不会算送达花巢打开，侧庭恢复；把风笔停回起点可再送一程，可尝试少碰撞、更顺畅的路线
潮生庭，(-12,-29)，高 1.1，风场主线完成后可达三朵高低不同的回声花；当下有声音的一朵发出波纹亲自走近发光花，收起风笔，停步 1.25 秒。听完一句后，下一朵苏醒奔跑经过或挥动风笔不会完成；局部静听进度温和消退，已听过的句子不回滚三段来信组成完整意象，花庭恢复；离庭再回来，可以重听，已恢复环境不被重置

主线通路由主线状态控制。探索支线没有借道越桥、提前进入下一幕或额外领取主线核心的权限。三庭核心平面与地形模块统一为半径 2.1 米，建筑、树木位于外围。

三庭来信共同指向终章，而不各自停留在一个小谜题里：雨庭的地址是“旧日”，岑留下“记住故乡，不必重复同一个春天”；风庭的地址是“远方”，船舷旧便笺请求先将种子送到避风处，再把余下的路交给生长；潮庭的地址是“眼前”，三段记录先回忆合拢的花曾保住雨声，再表达等待新雨的愿望，最后提醒种核只有两枚。玩家到终章时已经与三种愿望发生过具体关系，因此选择有情感重量。完成庭院不增加第三枚种核；永久开花与回信中记录的行为，是另一种被记得的方式。

主线现已用 explorationReply() 按三庭完成标志，在拾光册与终章回信分别记下描环、送种和静听的行为。上述接口已接入源码；最终发布页的显示仍须随新候选验证。

输入优先级与可读性

  • 默认左拖环看、右拖环看；只有按住空格或打开风笔工具时，拖动才写入世界风场。描环与引种不从普通鼠标悬停或镜头拖动获得进度；静听按角色靠近与停步判定，允许玩家安静环看。
  • 动作以世界 XZ 坐标判定，场地高度不会使同一画迹突然失效；模型不读取屏幕像素。
  • 当前目标只在靠近庭院时显示，不用三个浮动任务面板占满画面。远处以路、轮廓与微光引导。
  • 冷暖和形状同时编码状态：待完成风门有上方小光种，当前回声有扩散波纹，完成花朵真实展开。色觉差异或静音不影响任务可完成性。
  • 鼠标速度影响观感与运动，不拿极短反应窗口惩罚玩家。任何失败都不删除永久奖励。
  • 减少动态模式降低漂浮、转动和波纹扩散；动作规则与进度阈值保持一致。

代码边界与接入

spring-letter/src/exploration-model.js 只包含可独立测试的确定性模型：

createExplorationState()
restoreExplorationState(raw)
restartExploration(state, 'rain-grove')
stepExploration(state, input, delta, anchors)
// => { state: nextState, signals, context }

stepExploration 不修改输入状态、玩家、主线、手势或存储。时间、玩家坐标和手势由调用方传入；异常帧时间限制在安全步长。恢复旧档时缺失探索字段得到空白三庭，物理速度不跨存档复活，风种回到最后已通过的风门。

spring-letter/src/exploration.js 是独立 Three.js 表现层：

const exploration = createExploration();
scene.add(exploration.group);
const signals = exploration.update(time, dt, {
  player: state.player,
  gesture: { active, position, velocity, strength, mode: 'weave', released },
  progress: state,
  exploration: state.exploration,
  reducedMotion: state.settings.reducedMotion,
  interactive: mode === 'play' && !focus && !hadPinch && touchPoints.size < 2,
});
const { nearTarget, key, title, objective, hint, progress, completed, total } = exploration.context;

表现层只把模型产生的新探索字段写入传入的 state.exploration。它不会修改主线、不处理键盘、不拥有相机、不自行播放声音。signals 是当帧事件，不是永久队列：

事件用途
discover首次走近庭院；可播放短提示
checkpoint画迹点亮新花/通过一道风门；提供 step / total
soft-return乱流或越界的温和反馈；含 reason / text
echo当前回声位置与接近程度；根模块可做轻量音高、声像提示
memory听到一句具体来信；含 text
complete完整送达；first 区分首次与重演，避免重复发放奖励
reprise完成风庭后把风笔放回起点，再送一程

targets、context、signals 向根模块提供读取接口；dispose() 可重复调用。几何、花瓣、纹理全部为本项目程序生成的原创资产；没有外链纹理、付费接口或第三方模型包。

验证记录与仍需现场验证的边界

原模型验收为 11 项；加入损坏描环恢复回归后，node --test tests/exploration.test.js 为 13 项通过。覆盖：顺逆方向画环；静止、跳点、远程与锁定场景不能误触；种子真实积分依次过门、松手落巢与重演；软退保留门序；回声三点实走与静听；纯函数不改输入；旧档和损坏字段恢复；表现层奖励边界、有限矩阵与资源释放；旧版主存档缺探索字段仍保留原进度；轻缓动态不改变操作规则且回声线索保持可见；保留给相机或模态界面的输入不会被模型当成送达/静听。新增两项实际走过主存档恢复入口：不可能合法遗留的达标描环不得在零输入时自动奖励；合法部分描环与已获奖励的重演进度仍保留。

可复用经验

  1. 让动词分化：连续画迹、惯性护送、停步倾听，比增加三个相同“收集”按钮更能形成节奏。
  2. 先决定成功时世界哪里改变，再决定 UI 显示什么；永久奖励应在返程继续可见。
  3. 风笔与相机争用同一拖动会让两个系统都变差，输入意图必须显式分开。
  4. 手势的世界路径需要连续性验证，点击、跳点、开场自动动画不应代替亲手完成。
  5. 玩家应该理解失误：乱流石有可见位置，回退有上一道门，静听有可见波纹，不把失败隐藏在内部数值中。
  6. 原创程序化资产免去了授权与网络依赖，但仍需要材质、层次、比例和镜头下的持续审查。
  7. “风笔不活跃”不一定表示玩家松手。双指缩放、模态界面、失去焦点属于输入被保留的状态，不能触发依赖放手的任务。
  8. 屏幕宽度不等于输入设备。横屏手机会越过桌面宽度断点，粗指针与短高度需要独立审查。
  9. 提示必须对应当下物理状态：需要归尘才能留光时，应明确提示松手；慢笔本来不该扬尘，就不能给所有笔触一个固定散开底值。
  10. 一次测试通过只覆盖被执行的输入序列。雨庭双指不误画，不能推出末门风种双指不误送达；需要保留已复现问题的独立回归。
