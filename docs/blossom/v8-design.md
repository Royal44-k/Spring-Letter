# 春信 0.6：让一封信改变一处生活

2026-11-21。用户授权自主研究、设计、实施和本地验证；沿用桌面浏览器与免费本地素材，不发布或收费。

## 产品判断

核心受众假设是喜欢自然观察、温柔空间解谜、短篇叙事和个人创作的玩家。作品的承诺应是「用花尘修好一处生活，再决定把春天留给谁」。商业可行性尚未由真实玩家或付费行为验证；本轮交付可试玩的产品候选与验证材料。

现有短板：三庭追风仍以收集为中心；六条支线回报轻，行动很少改变之后的玩法；开场提示过多；唯一存档可被误点覆盖；低多边形庭院与宏大叙事的尺度不一致。不能靠菜单数量、文字量和测试数量补足。

## 本轮闭环

来信 → 走向具体庭院 → 转动叶脉石，让花尘沿真实接通的路流动 → 在两个都合理的照料对象间选择 → 环境生长与回信 → 新能力帮助下一程。

雨庭「一瓢水的去处」：三转子、两分支，给老树或新芽。风庭「夜渡之前」：绕行与止漏，把春风留给护种帆或迎客灯。潮庭「留给下一声」：双源分流，将旧声和新声接到同一个收信端。操作语法一致，条件递进，无计时惩罚。直接点场景中的转子，也可方向键选中、Enter 转动；撤销、提示、离开后继续。接通只预览，选择「留下这份照料」才完成；可回来重选，不隐藏惩罚。

三封信的两种选择给予同等功能奖励，差异体现在场景和回信，避免把情感选择绑定数值强弱。雨庭恢复踏风气息更快；风庭开启已完成庭院的花尘往返；潮庭给予金色花灵的开合预告。主线两枚种核的结尾引用这些真实行动。原花尘练习、追风、支线继续可玩。

视觉采用湿石、叶脉、温暖信纸、粉瓷花心与青绿水面；回路不是悬浮科技按钮。花尘颜色来自当前主花系列，流路从发信端逐段亮起，末端花冠真正展开。优先保证路径和结果可读，再加柔光/水纹。新玩家界面只突出一个当前行动，其余放入信册；暂停可靠，键盘和窄屏保留完整操作。

## 工程与交付

纯规则模型与三维呈现、界面分开；游戏主状态持久化委托旋转/选择，瞬时流量不写档。统一存档服务原子写入主档，保留新旅程之前的备份，导出/导入先校验预览；识别损坏、未来版本、多标签冲突和写失败，不能静默覆盖。保留旧版本资产与验证证据。
