# 追风送春：从观看花，到亲手带回春天

2026-11-20。独立《花漾年华：待寄出的春信》v7 玩法模块。本文记录设计依据和接线合同，不把规则单测当作整机可玩性或玩家盲测。

## 这次改变的核心

上一版允许看花、改花、等花归形，但主要目的仍是看一段漂亮变化，玩家选择很少。新核心让弥把散开的花尘带到世界里：出发、选路、踏风拾取、决定何时返航，再亲手把春风送回花巢。风声、音乐密度与随行花尘应共同反馈连续运动。

已经放弃的两条方向是“再加一页收集清单”和“把首花改成更严格的按键节奏关”。前者不改变行动，后者把本来要舒展的体验变成精密门槛。当前采用自由次序的空间路线，并让风险来自是否绕远、怎样使用有限踏风、能否连起一段行程。

## 自主参考，采用什么

1. **Flower：行为改变身边的世界。** 官方介绍明确描述收集花瓣与环境变化相连，方向由玩家引导。本作借鉴行动后的空间回应：成功带回的花灵在花巢周围长出不同数量的花簇，而不只增加一个完成图标。没有复制其模型、音乐或关卡。[thatgamecompany 官方 Flower 页](https://thatgamecompany.com/flower/)
2. **Journey：移动本身与远处目标共同构成旅程。** 官方描述滑行、飞越遗迹、向山峰前行及路上的陪伴。本作据此保留可见花巢作为返航目标，把踏风的动作、轨迹和空间方向放在面板前面。当前不实现在线联机、飞行或 Journey 的角色能力。[thatgamecompany 官方 Journey 页](https://thatgamecompany.com/journey/)
3. **Sword of the Sea：动作反馈要跟随玩家控制。** Giant Squid 首席动画师说明转向差值、速度、倾身与附加动作怎样使操控有流动感。本作借鉴“速度、转向、角色姿态、音画反馈共用实际运动信息”的原则；原游戏的多维姿态系统和滑板物理不在这里复刻。[Giant Squid：Animating The Wraith](https://giantsquidstudios.com/Animating-The-Wraith)

以上为一手来源支持的观察；下面的花灵、回巢结算、计分和风结是本项目的设计判断，不是声称上述游戏有完全相同的机制。资源、造型和规则均原创程序实现，无购买素材或收费生成调用。

## 三段练习，三种重点

|花庭|位置与开启条件|行动与取舍|
|---|---|---|
|第一阵春风|出生庭花巢 `(3,4)`，从新旅途就可进入|8 朵自由选择，至少带回5朵；5朵银白不要求踏风，3朵金色更值钱并回复踏风。先学走近拾取、选择路线、回巢。75秒，不必全收集才能开启主路。|
|穿过回旋的风|风廊花巢 `(3,-12)`，首幕开启后|10朵至少带回6朵；两道移动风结在内圈穿行。走安全外沿、绕远追金灵，或消耗踏风穿过风结，三者有不同连锁结果。80秒。|
|把远方带回来|终庭花巢 `(3,-42)`，桥岸开放后|10朵至少带回7朵；银白5朵、金色5朵，需实际使用踏风。90秒。金色花冠每4.2秒有约2.65秒张开期，花瓣平滑开合、亮度同步；张开时踏风掠过才可收取，闭合可换路或稍等。该规则已实现并通过CPU检查，最终普通输入仍待根任务复验。|

三个活动都只使用现有可走圆盘。初庭及风廊活动不要求临时造桥；终庭活动在主路桥完成后才出现，不在不可走水面布奖励。节点动态轨迹和风结坐标已逐时间取样调用 `supportAt`，不是仅看平面设计图猜可达。

## 玩家可以做出的决定

- **带够就回，还是多走一段？** 达到最低数只打开结算资格，不自动结束。玩家返回起点花巢按 E 才兑现这一次春风；也可继续带回其余花灵，争取完整和声和更丰盛的巢边花簇。
- **花灵不是同一种奖励。** 银白走近即可拾取，金色需要在移动中踏风掠过；金色得分更高，也补回更多踏风，因此是一种可以续航的路线选择。
- **连奏鼓励连续行程。** 两次获得间隔超过5.5秒，连锁从头开始；已收花灵不消失。站在花灵旁不动不会自动拾取，回头反复经过也不能刷分。
- **风结有恢复空间。** 普通步行触碰回旋风会打断连奏，发出短促提示并请求半秒迟滞；踏风可穿过。已有花灵仍跟随，不将一次失误放大为重新走完整关。
- **完整与速度可以兼顾。** 结算分由花灵种类、连奏和少量剩余时间构成；花巢外观由带回数量升为1—3级，最高档要求全收集。最佳分与最高外观独立保留，较弱的重玩不会覆盖之前的最好记录。

期限为宽容的旅程节奏，不是难度炫耀。超时只结束本次活动，既有主线、种核、支线与最好成绩不受影响。走远离开庭院2.5秒会收起活动；主动取消同样不删除成绩。暂停设置、切换不互动状态时暂停计时并清除上一帧拾取轨迹，避免恢复时虚假穿过节点。

## 根模块接线合同

新文件仅为 `spring-letter/src/resonance-model.js`、`resonance.js` 和专门测试；主循环、界面、音频、角色控制由根任务接线。

```js
import {createResonance} from './resonance.js';
import {RESONANCE_SAVE_KEY} from './resonance-model.js';
const resonance = createResonance({saved: localStorage.getItem(RESONANCE_SAVE_KEY)});
scene.add(resonance.group);
const signals = resonance.update(time, dt, {
  player: state.player, progress: state, dashing,
  interactive: mode === 'play' && !focus,
  reducedMotion: state.settings.reducedMotion
});
// E 在花巢附近开始，活动中在同一花巢结算。
const result = resonance.attempt(state.player, state); // {ok, signals, reason}
// cancel() 返回 signals；reset(saved?) 清掉正在进行的行程。
// 完成时写 persist()，它只保存获得的成绩，不保存半跑或主线。
```

`context` 提供 `id/title/near/active/atStart/readyToBank/actionLabel/goal/total/collected/progress/score/combo/remaining/best/grade/start/objective/hint`。活动中的 `near` 代表当前活动，而是否可 E 结算要看 `atStart` 与 `readyToBank`。`snapshot()` 提供花灵 `{id,x,z,kind,type,collected,requiresDash,open}`、危险位置、三处花巢、活动及已获记录，可供只读小方位盘和普通输入测试使用。第三庭的 `open===false` 可在方位盘上淡化显示；前两庭及银白花灵的 `open` 始终为真。

信号：`start`（开始并补满踏风）、`collect`（含节点、种类、分数、连锁、位置与0.12/0.32踏风补充）、`ready`（可回巢）、`bump`（断连与0.55秒迟滞请求）、`complete`（第一次/本次分数/最好分/数量/外观等级/补满踏风）、`timeout`、`cancel`、`hint`。活动模块绝不直接写主线；根任务可在第一次 `complete` 且 `id==='dawn'` 时将首幕路径唤醒，同时保留原花散聚完成路线，兼容旧存档。

视觉由实例化曲面花瓣、种羽丝带、花灵光点、运动拖尾和收取绽放构成。花巢从地面升至约2.4米，靠轮廓而非巨型箭头提示位置；返航资格获得后，低矮花粉沿角色—花巢方向流动。没有新增实时点光源或独立后处理通道。

## 验证与边界

13项CPU检查已通过：全动态位置可走、开启条件、最低数不自动结算、金灵移动踏风与防重刷、完整和声/较弱重玩、暂停/站立/跳跃坐标不误收、跨帧穿过、风结容错、超时与取消、坏存档和资源销毁，以及第三庭时间窗宽容度、两处后段庭院全路线与回巢结算。首次测试发现测试导入错误及“离开金灵当帧已拾取但测试未收集该步信号”的测试记录问题，修正后通过；没有据此伪称发现并修复实机玩法故障。

加载接线时应在着色器预热前做一次 `update(0,0,{player,progress,interactive:false})`，先分配实例颜色和矩阵；这一步不计时或推进规则，避免首进活动才增加实例颜色着色变体。使用者需在移除模块时调用 `dispose()`；它幂等释放全部自有几何、材质与纹理。

尚待根任务验证：普通输入走通三庭，玩家是否理解回巢、镜头转动后方向是否清楚、方位盘是否有帮助，实际踏风消耗与金灵补给是否平衡，音画反馈、手势互斥、真实页面存档和终庭种核是否互相干扰。没有真实新玩家盲测；“好玩”不能由单元测试数量直接证明。
