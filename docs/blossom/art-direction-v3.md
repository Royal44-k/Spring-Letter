# 《花漾年华：待寄出的春信》制作定稿补充

2026-11-18｜v3。沿用已经两轮评审的[完整设计](design-proposal.md)与[叙事玩法蓝图](experience-blueprint.md)，本篇补足实际制作的视觉语言、参考应用和工程边界。用户本轮明确授权先完善、随后执行开发；不再把开发停在方案确认上。

## 1. 工作名与作品的独特之处

工作名采用用户建议《花漾年华：待寄出的春信》，英文短名Spring Letter。原《花尘之间》保留为研究档案阶段名称。主题仍为一枚花灵在保存故乡季节的方舟花庭中醒来，让记忆参与新生活。

“春信”是玩家一路组织出的光、花色、运动与回应。终局用两枚种核安排记忆、眼前四季和远方播种中的两项；每种安排留下可停留、可触摸的尾声。通关后可以在本地保存一张自己的画面作为春信，不连接邮件、社交账号或自动发送服务。

作品的标志性瞬间：一朵仍半开的虹彩百合沿自身花瓣散成有厚度的点场，指针拨开局部，花尘绕过玩家的作用区，再回到花、同伴或可走结构。材质的形体与粒子的形体必须对应。美来自连续变化，以及变化之后玩家有了新的路。

## 2. 视觉约束与主动参考

复核原视频后，视觉优先级是：六瓣百合的曲率与多花头构图、银/晶/自然三种材料身份、浅水接触反馈、表面点云的密度和局部恢复。银花不能由彩虹基础色替代，点云不能由全屏随机星星替代。

近期主动拓展的参考及第一方证据会记录在[网站研究](research-sites-v3.md)与[免费资源清单](free-assets-v3.md)。已可采用的方向：Sael的Prism Room把复杂光学效果收束为清楚的输入与少量可比较状态；Soap Bubble把薄膜虹彩绑定观察角度与厚度。对本作的转化是：参数少而有因果；材料变化跟随空间；近景和游戏状态始终连续。网站浏览可免费，不等于其图片、代码和模型可直接商用；来源不明的资产不打包。

| 色彩角色 | 制作起点 | 用法 |
|---|---|---|
| 珍珠雾 | #E7E2ED | 明场天空、浅水反光，保留中间调 |
| 月银 | #CFD6E5 | 银花环境与石台边缘，靠照明产生层次 |
| 暮紫 | #21172F | 夜场背景，避免纯黑吞掉形体 |
| 花粉玫 | #D8A1D7 | 点云上层与短暂受激区域 |
| 冰川蓝 | #91BFE8 | 点云下层、水波与风的方向 |
| 春信金 | #D4B77B | 花蕊、关键回应与自然花的稀疏暖色 |

标题采用系统衬线中文字体（优先华文中宋/宋体），正文用系统无衬线，界面数字与英文用Georgia/系统字体。首版不下载许可未查的字体，不把联网字体设为加载前提。游戏的核心界面是画面本身：主菜单让实时主花占据右侧/中部，左侧只保留工作名与进入按钮；游玩时只留当前目标、当前操作与设置入口。

```text
工作名 / 当前庭院                         声音 · 昼夜 · 设置

           浅水、拱廊与远景花冠
                   实时花 / 同伴 / 粒子

  当前目的                         靠近时出现的有效动作
          聚焦时的花开弧线 / 少量锚位
```

鉴赏台的滑杆、材料与参考键位保留；主线沿用统一聚焦，不把一屏技术参数交给玩家。界面不显示shader、GPU后端或内部状态名称；性能数据仅在开发诊断模式出现。

## 3. 本次执行的顺序与范围

先建立独立可运行项目`spring-letter/`，不改旧项目入口、角色、场景或音轨。按以下顺序推进并持续验证：

1. 主花、浅水、棚光、三材质、连续开合；用固定机位与原帧比形体和明暗。
2. 稳定表面采样、点云排斥、散聚、昼夜切换；反复操作、中途反向。
3. 游玩场景、低空滑行与相机、P1/P2、杯纹与同伴回应、存档。
4. P3安全台与可回收结构、P4两核三用途、提交/回看、鉴赏和本地摄影。
5. 常规输入连续游玩、各结局、失败恢复、失焦/重载、设备帧时与截图评审。

这形成一套可从开场走到尾声的首版。30–45分钟仍是完整精修篇章的目标，不会通过把原型走一遍就宣称已达到该时长。每阶段完成情况、视觉差距和测试证据写入[开发记录](development-log.md)。

## 4. 实现约束

Three.js锁定本地已核对的r185，WebGL2主线；Vite独立入口。可复用已安装的开源依赖以避免重复下载，独立package声明精确版本。制作资产为原创参数曲面和已核实CC0环境，不调用计费API。免费资源一旦采用，就保存本地、附来源与SHA，运行时不依赖素材站在线服务。

花使用预制闭合/开放曲面与连续插值，茎、叶、花蕊分别建模；采样来自实际网格表面。粒子优先GPU状态纹理与有界力场，受限设备退化为较低密度的稳定形变；逻辑光团与视觉粒子分开。水面采用有限波源与受控反射，焦散称视觉近似，不宣传为实时路径追踪。

世界、渲染和玩法模型分开。有限资源、占用保护、终局提交和存档用纯逻辑测试约束；视觉美感通过截图和连续操作检查。性能目标沿用v2预算；先测实际设备，不引用参考视频上的118FPS作为本作成绩。

## 5. 本次参考案例的正确用法

继续追查Fable 5.2射击游戏的原提示、初版和修订版。可借鉴具体美术简报、持续工具执行、独立审美评审、正常输入录像和真实帧时记录；案例的强视觉不能替代对完整游戏系统与资产许可的核查。新增证据单列[射击案例复核](fps-case-v3.md)，不将二手转述写成直接看到的事实。

零素材采购与免费工具路线不意味着制作工作没有成本。此处执行采用本会话已有能力与本地开源工具；不另买模型额度、提示库、3D资产或生成服务。遇付费订阅墙则换公开来源，不用免费试用作为生产依赖。
